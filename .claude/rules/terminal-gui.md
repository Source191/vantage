# Terminal.Gui 2.5.0 facts

- Instance API: `Application.Create().Init()`, `app.Run(window)`, `app.RequestStop`, `app.Invoke`, `app.AddTimeout`; set `app.Driver.Force16Colors = false` or the palette collapses to 16 colours.
- Never block the UI thread on an awaited call (`GetResult()`): Terminal.Gui installs a synchronisation context and the continuation deadlocks. It showed only after an attach-and-return, which the console no longer does (a session opens in its own tab); the hand-off check was built because of it.
- Focus roles: a scheme with Focus equal to Normal hides focus everywhere; ListView draws the selected row with Focus when focused and Active otherwise; a TextField needs its own background or it is invisible when empty, and a read-only TextField is drawn with the ReadOnly role once it loses focus.
- Dialogs: a Button with IsDefault takes the initial focus; set focus from the dialog's `Initialized` event, not before `Run`. A Dialog of Height 12 has 8 usable rows and the button row overdraws the last. A Label that receives text later needs a fixed Height and non-empty initial Text. A TextField's Enter raises its own `Accepting`; KeyDown handlers on the field or dialog do not see it. Ctrl+C in a TextField copies its selection through `app.Clipboard`, which Windows Terminal passes through when it has no selection of its own.
- A Label reads `_` as its hotkey mark unless `HotKeySpecifier` is set to U+FFFF before `Text` (node_repl showed as noderepl). A Dialog holding one Label per line from Y 1 and a Button with its shadow row drew nothing in its last two content rows at Height lines + 6 (the same loss as a single multi-line Label through `Confirm.Ask`), so `MemoryDialog` uses lines + 8; this is two rows fewer than the "8 usable rows at Height 12" rule above allows, and the difference is unexplained.
- Tooltips: `app.ToolTips.SetToolTip(view, text)` shows on hover (the label's MouseEnter), anchored under the pointer's view. A table raises no position reports unless `MousePositionTracking` is true, and its tooltip is evaluated only on entry, so the column-header tooltip is shown by hand (`ApplicationToolTip.ShowFor` from `table.MouseEvent` with `ScreenToCell(position, out header)`, hidden on leaving the header); Terminal.Gui draws a tooltip at its target's bottom-left (`ToolTipHost.SetPosition` over `FrameToScreen`), so under the whole table it covered the detail pane, and `TableBody` targets a zero-width view laid over the header (or, for a Config row's description from `IScreenDefinition.RowTip`, over the row) at the pointer's column, which puts it on the rows just under. It still shifts a wide tooltip left to fit the screen. The headless terminal can hover: send SGR motion `\u001b[<35;col;rowM` (1-based) after 8000 ms.
- The help is `Tui\HelpDialog`: a read-only `TextView` in a dialog as tall as the text needs, up to nine tenths of the screen, with focus in the text so the arrow keys and PageUp and PageDown scroll it. A Dialog reserves its own button area, so the box is `Y = 0` with `Dim.Fill()`; reserving rows for the button as well cuts the last lines. The sessions help (26 lines) fits whole at 120 x 36.
- Removing a SubView from `Tabs` selects another and raises `ValueChanged`, so `ConsoleScreen` disposes its tabs under the binding guard, or quitting shows (and logs) the other tabs.
- `OpenDialog` (`OpenMode.Directory`, `AllowsMultipleSelection`) is the roots dialog's folder picker, checked by a spike on 30 October 2026: it derives from `Dialog<IReadOnlyList<string>>`, not the plain `Dialog`, so `DialogTabTitle.Apply` takes a `Runnable`, and it writes its own title as the tab title like any Runnable. It opens at 96 x 28 in a 120 x 36 terminal and takes `Palette.Focusable` for most of its parts. Focus starts in its path box; Tab reaches the folder list, Down moves the selection (the path box follows), Shift+Down extends it, Enter in the list confirms rather than opening the folder, and Space does not toggle a row. `FilePaths` answers the folders in the order chosen (`Path` is empty for several), and `Canceled` is true after Esc. The headless terminal drives it.
- `OpenDialog` in `OpenMode.File` is the Open folder with dialog's picker for a Custom executable. Read from the 2.5.0 assembly (decompiled with ilspycmd, 1 November 2026), not observed: `AllowedTypes` is a `List<IAllowedType>`, and `new AllowedType("Programs", ".exe")` matches by the path's ending, ignoring case; with any allowed type in File mode the list shows folders and only the files that match (`FileDialogState.GetChildren`), the first type becomes the filter and a types drop-down is shown, and accepting a typed path of another type is refused in the dialog with its own wrong-type line. `MustExist` defaults to false, so a typed path that does not exist is accepted (F5 checks it), but a folder typed in File mode is refused. Enter on a folder in the list opens it and on a file accepts it; `Path` is the path box's text (set before `Run` it opens there; left empty it becomes the current folder at `EndInit`), and with one file allowed `FilePaths` answers `[Path]` once accepted and an empty list otherwise; `Canceled` is `Result == null`, which the Cancel button and Esc leave. `OptionSelector.Labels` has a public setter that disposes and rebuilds every option (`SelectorBase.CreateSubViews`), so the dialog retitles the existing options' `CheckBox`es instead, which keeps focus where it is.
- `app.AddTimeout` callbacks keep running at their interval while a modal dialog runs its own `app.Run`, so the console's refresh timers and `Heartbeat` tick under a dialog. Observed on 1 November 2026 with Terminal.Gui 2.5.0 (a throwaway program in the headless terminal: a 250 ms timeout beat 18 times, about 280 ms apart, during a 5-second dialog opened by a key) and read from the decompiled assembly: the application has one `TimedEvents`, the nested `ApplicationImpl.Run` loops `Coordinator.RunIteration()` like the main one, and `ApplicationMainLoop.IterationImpl` ends with `TimedEvents.RunTimers()` whichever runnable is on top. `RunTimers` holds its lock while it calls each callback, and `app.Invoke` from another thread is `TimedEvents.Add(TimeSpan.Zero, ...)`, so a dialog opened from inside a timeout callback blocks every other thread's `app.Invoke` until it closes (observed: the background close request never returned), and by the same reading so does one opened from inside an `Invoke` callback, which runs as a zero timeout (read, not observed); the UI thread re-enters the lock, so timers still fire.
- A `Dialog` run as the application's first runnable, before the main window (the What's new dialog on the first start of a new version), raises `IsModalChanged` with true like any dialog, so `DialogTabTitle` writes its tab title, and the window run after it writes its own (observed 1 November 2026, Terminal.Gui 2.5.0: a throwaway program in the headless terminal wrote `Initialized`'s title, then the modal title, then the window's; Esc closed the dialog and the window followed). The `count` command reads plain text only, so a title is found in `drive-raw.txt` itself or by a smoke step's title marker.
- `TextView` is obsolete (pragma CS0618) but still the wrapping multi-line box. `OptionSelector` replaces RadioGroup. Table rows take colours through `TableView.Style.RowColorGetter`.
- `Tabs` (no `TabView` or `TileView` in 2.5.0) shows each SubView as a tab titled by its `Title`; the strip takes three rows (outer border, titles, separator) and the selected tab's body starts on the fourth, framed. Its span is each title's length plus a border cell either side, adjacent tabs sharing one (`GetTotalHeaderSpan` and `Border.TabOffset` are not public), so the counts label sits after it on the title row. The selected tab is the focused SubView, so a tab's view has `CanFocus = true`; setting `Value` and clicking a title both raise `ValueChanged`, so the console applies a click under a binding guard. A spinner redraws only its own tab, title box and frame included, which lands on top of the shown tab and closes its edge under the title (the Worktrees tab's waiting spinner, which turns while its first scan runs and the tab may be hidden, did this from the first frame), so `ConsoleScreen.Show` tells both tabs which is shown (`ITabBody.Shown`) and a hidden tab keeps its spinners still; a table refresh is safe because `FrameChanged` redraws the whole window. It binds the arrow and paging keys to moving between tabs, which took Up and Down from the table, so `ConsoleScreen` removes those bindings from the strip and both tab views; every other key still reaches the window's `KeyDown`. `Shortcut` draws its command text before its key (`Attach  Enter`) with Terminal.Gui's own key names, so the key bar is label pairs with `MouseEvent` handlers on `MouseFlags.LeftButtonClicked` instead (checked by a spike, 30 October 2026).
- A table that cannot take focus draws its selected row with the scheme's Active role, which Terminal.Gui derives as a lighter shade when a scheme leaves it unset (black on cyan came out as bold dark grey on bright cyan, a red block as pink): `Palette.SelectedRow` names those colours and sets every role, and a cell that keeps its own colour there (the TAB block, `CellPaint.Fill`) is drawn with `Palette.SelectedRow(colour)`.
- `SpinnerView.AutoSpin` is safe to set repeatedly and before the view has an `App` (`EndInit` adds the timeout later); the default style is Line, and `SpinnerStyle.Dots` renders in the headless capture.
- `ImageView` (Terminal.Gui 2.5) takes a `Color[,]` and draws it through [Sixel](https://vt100.net/docs/vt3xx-gp/chapter14.html) or [Kitty](https://sw.kovidgoyal.net/kitty/graphics-protocol/) when the driver reports support (`app.Driver.SixelSupport`, detected at start-up; Windows Terminal draws Sixel), fitted to the view at `ZoomLevel` 1; without support it colours one cell per pixel, so `VantageIcon` stays hidden then. The icon's pixels are `assets\icon\vantage-48.rgba` (`*.rgba binary` in `.gitattributes`), written by `tools\New-IconPixels.ps1` (the icon from `VantageMark.ps1` with `-Outline`, an edge in the frames' grey drawn inside its dark tile, which otherwise vanished on the console's black; white was too stark and the mark without its tile, `-NoTile`, read worse; `VantageIcon.Fit` makes the view as many cells wide as its one row is tall in pixels, from the reported cell size, because a fixed width stretched the icon) and embedded in the Tui assembly; the headless terminal reports no image support, so its captures never show the icon.
