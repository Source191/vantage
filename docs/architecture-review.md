# Vantage architecture review

Date: 24 October 2026, re-anchored the same day to `main` at 5d01bfb (version 0.2.0, after the tab-focus, own-tab and spinner changes). Scope: `src\Source191.Vantage` (about 5,300 lines in one project). Tests and `tools\HeadlessTerminal` are mentioned only where a split affects them. Nothing here has been changed in code; this is a proposal.

**What is already right:** the reducers are pure and fully tested; fakes sit only at the process, operating system and transcript boundaries, with no NSubstitute anywhere; value objects (`SessionName`, `WorktreeSlug`, `RepositoryPath`, `SiblingWorktree`) and rule objects (`RemovalDecision`, `WorktreeHealth`, `DisplayState`) hold the domain logic; tests are named as behaviours. The folder names (Domain, Adapters, Actions, Launch, Screens) show hexagonal intent. The problem is that nothing enforces it, so dependencies have started to run in every direction.

## 1. Why the single project is straining

- **Actions and Screens are cyclic:** all four files in `Actions` import `Source191.Vantage.Screens` for `SessionRow`, `WorktreeRow` and `ViewEffect` (`Actions\SessionActions.cs:5`, `Actions\TabOpener.cs:4`, `Actions\TerminalEffects.cs:2`, `Actions\WorktreeActions.cs:6`), while `Screens\Tui\SessionsScreen.cs` and `Screens\Tui\WorktreesScreen.cs` import `Actions`. That cycle is the one thing that makes a project split impossible today.
- **Ports live beside their adapters:** `IClaudeCli`, `ITranscripts`, `IGit`, `IProcessRunner` and `IWindowsTerminal` all sit under `Adapters.*`, so `Actions`, `Launch` and `Screens` carry twenty `using Source191.Vantage.Adapters.*` lines between them. The application layer cannot move without the adapters following it.
- **StateStore has no port and five jobs:** `Adapters\State\StateStore.cs:10` is a concrete class used directly by `SessionActions`, `TabOpener`, `OwnTab`, `WorktreeActions`, `LaunchService`, `LaunchWorkflow` and `SessionRowEnricher`. It owns tab registrations, recent repositories, created worktrees, session descriptions and config. Eight test classes create a real temp folder to get past it (`StateStoreShould`, `SessionActionsShould`, `TabOpenerShould`, `OwnTabShould`, `WorktreeActionsShould`, `LaunchServiceShould`, `LaunchWorkflowShould`, `SessionRowEnricherShould`), so sociable tests that should be in-memory touch the disc.
- **An adapter depends on the UI:** `Adapters\Diagnostics\HandoffLog.cs:13` takes a `ViewEffect`.
- **Screens is three things:** pure reducers and their records (`SessionsView.cs`, `WorktreesView.cs`), I/O read models (`SessionRowEnricher.cs`, `WorktreeInventory.cs`) and Terminal.Gui rendering (`Tui\`) share one namespace.
- **Program.cs is not only wiring:** CLAUDE.md allows `Program.cs` to be untested because it is wiring, yet `Program.cs` holds the two-screen loop, mutates `sessions` to handle `JumpToSession` at line 108 (a reducer concern), writes the tab title and colour escapes at start, quit and after every hand-off (lines 75 to 77, 100 and 117), and defines `RunHereAsync`, `LoadAsync` and `ScanAsync` from line 123 to the end at 162. None of that is tested.

## 2. Recommended project layout

Four projects, so the compiler enforces direction.

| Project | Holds | References | Packages |
|---|---|---|---|
| Source191.Vantage.Core | Domain; ports (IClaudeCli, IGit, ITranscripts, IProcessRunner, IProcessRegistry, IWindowsTerminal, a narrow IFolders port, the split state-store ports) with their request, result and exception records; use cases (Actions including OwnTab, Launch, SessionRowEnricher, WorktreeInventory, RepositoryCatalogue); reducers, view state, rows, effects | none | none |
| Source191.Vantage.Infrastructure | ClaudeCli, GitCli, ProcessRunner, ProcessRegistry, file-backed state, the IFolders implementation, ClaudeExecutable.Locate, WindowsTerminal, UiAutomationTabs, TabEscapes, ConsoleRecovery, FileLogger, ClaudeTranscripts, WorktreeIncludeCopier | Core | FileSystemGlobbing, Logging.Abstractions, Interop.UIAutomationClient |
| Source191.Vantage.Tui | Screens\Tui: screens, dialogs, table sources, Palette, KeyMapping | Core only | Terminal.Gui |
| Source191.Vantage (exe) | Program.cs and a small tested command router | all three | none |

The rule for Core is: no `System.IO.File` or `System.IO.Directory`, no `System.Diagnostics.Process`, no Terminal.Gui. `System.IO.Path` is pure string work and stays. Three classes currently break that rule and need the `IFolders` port (exists, enumerate directories, read lines): `WorktreeInventory` enumerates roots, reads `.git` files and counts leftover files; `RepositoryCatalogue` enumerates roots; `LaunchWorkflow.Plan` passes `Directory.Exists`. The alternative is to keep those three read models in Infrastructure with only their row types in Core, but the port is cheaper and gives `Core.Tests` an in-memory fake instead of temp folders.

Keep `PackAsTool` on the exe. A tool package includes referenced project outputs, so it still ships as one nupkg; confirm with `tools\install-local.ps1` straight after the cut.

Tests follow the same lines. `Core.Tests` is pure and fast with no temp folders. `Infrastructure.Tests` takes the real-git, real-process and real-file tests: `GitCliIntegrationShould`, `ProcessRunnerIntegrationShould`, `ProcessRegistryIntegrationShould`, `StateStoreShould`, `WorktreeIncludeCopierShould`, `ClaudeTranscriptsShould`, `FileLoggerShould`. The five `HeadlessTerminal\*Should.cs` tests belong beside the tool in `tools\HeadlessTerminal.Tests`, so the app test project stops referencing a tool.

**Fallback:** if four projects feels heavy for five thousand lines, two projects (Core, and the exe holding adapters plus Tui) still fixes the boundary that matters: nothing in Core may reference Terminal.Gui, System.Diagnostics.Process, System.IO.File or System.IO.Directory.

**Migration order** (each step keeps the build green and is its own commit):

1. Inside the one project, move `SessionRow`, `WorktreeRow`, `Key`, `ViewInput`, `ViewEffect` and the two reducers out of `Screens` into an `Application` namespace; move `SessionRowEnricher` and `WorktreeInventory` there too. `Actions` then depends on nothing the Tui owns.
2. Move the five interfaces plus `IProcessRegistry` into `Core.Ports`, and with them the records they return or throw, or it will not compile: `GitWorktreeEntry`, `GitException`, `ProcessRequest`, `ProcessResult`, `TabLaunch`, `TerminalException`, `StartResult`, `StartOutcome`, `ResumeResult` and `VantageConfig`. `PowerShellScript.Quote` and `Invoke` are pure string building and go to Core with the `TabScripts` factory from section 3; `Encode` and `WindowsTerminalArguments` stay with the adapter. Add the `IFolders` port and give `StateStore` ports (see section 3); make `HandoffLog` log a string.
3. Pull the screen loop out of `Program` into a tested `ScreenLoop`, `vantage here` into a `HereCommandRunner`, and argument parsing into `CommandLine.Parse(args)` returning a small union. Make `JumpToSession` a `ViewInput` that the sessions reducer handles.
4. Add one architecture test (ArchUnitNET or NetArchTest.Rules; both are current) asserting the direction, so steps 1 to 3 cannot regress before the physical split.
5. Cut `Tui` out first; it is the cleanest cut because only `Screens\Tui` moves.
6. Cut `Infrastructure`.
7. Rename what is left `Core`.

**Collateral to update:** `.github\workflows\check.yml` and `.github\actions\build-test-pack\action.yml` test paths; `tools\install-local.ps1`, which packs `src\Source191.Vantage`; the test commands in CLAUDE.md; the Stryker glob `**/Domain/*.cs`, which still works if the Domain folder keeps its name; an `InternalsVisibleTo` in each new project pointing at its own test project, because `ConsoleRecoveryShould` reads internal constants and every Tui class is internal; and a `Directory.Packages.props` for central package versions once there are several csproj files.

## 3. Refactors and patterns, biggest payoff first

### Bugs and risks to fix first

These stand on their own and do not need the restructure.

- **Reason-string sniffing:** `Screens\WorktreesView.cs:202` `IsFinal` decides whether to offer force removal by searching the reason for `"session "` and `"locked"`. Rewording a reason in `RemovalDecision` silently changes behaviour. Add a `CanBeForced` field to `RemovalDecision`.
- **Unsynchronised cache:** `Screens\SessionRowEnricher.cs:16` `locations` is a plain `Dictionary` written from `Task.Run` loads. Loads fire every five seconds and after every action (`RunInBackground` calls `TriggerLoad`), so a slow git call makes them overlap. Use `ConcurrentDictionary` or serialise loads through a `SemaphoreSlim`.
- **Stale lookup:** `Screens\Tui\SessionsScreen.cs:116` resolves `StopSession` with `First(...)` over rows that may have refreshed since the key press; every other effect carries the `SessionRow`. Make `StopSession` carry the row.
- **Unsafe default:** `Screens\SessionsView.cs:7` has `HasTranscript = true` as an optional parameter, so a forgotten argument reads as "safe to resume". Make it required. The new `Loaded = false` defaults on both view states (`SessionsView.cs:88`, `WorktreesView.cs:35`) are the same shape but default to the safe side, so they are a smell rather than a defect.
- **Stringly typed config:** `Screens\Tui\LaunchWizardDialog.cs:63` compares `defaultBase == "Head"`. `VantageConfig.DefaultBase` should be the existing `WorktreeBase` enum.
- **Non-unique key:** `Program.cs:108` matches `JumpToSession` by session name, which is not unique. Carry the session id from `WorktreeInventory.LiveSessionIn` instead.
- **Scan cost:** `Screens\WorktreeInventory.cs:166` `CountLeftoverFiles` walks every leftover tree on every fifteen-second scan; a leftover containing `node_modules` or `bin` and `obj` makes the forty-second first scan worse. Cap the count or compute it when `d` is pressed.
- **Lost writes:** `Adapters\State\StateStore.cs:61` and `:93` are read-modify-write on `recent.json` and `sessions.json` with no lock, and `vantage here` and the UI can run at once. The one-file-per-record design already used for tabs is the fix.

### Structural refactors

- **One generic table screen:** `SessionsScreen` and `WorktreesScreen` duplicate `Run`, `TriggerLoad`, `OnKey`, `RunInBackground<T>` (`SessionsScreen.cs:230`, `WorktreesScreen.cs:209`), `Live.Build`, `Redraw`, `ShowBusy`, the waiting indicator, `RowColour` and `Text`: roughly 350 of their 820 lines, and the spinner change on `main` added to both copies. The reducers duplicate `Load`, `EditFilter`, `MoveSelection`, `Reselect`, `IndexOfSelected`, `Unchanged` and `Effect`, and both state records repeat `Filter`, `FilterEditing`, `Banner`, `Footer`, `Loaded` and `Title`. Introduce a `ListSelection<TRow>` component (filter text, selected key, load, move, reselect) composed into both states, and a `TableScreen<TState, TRow>` driven by an `IScreenDefinition` (columns, row colour, header hints, help text, refresh interval). The roadmap's next view then costs a reducer and a definition. This is the single biggest maintainability win.
- **Effects as the extension point:** the "leaves the screen" classification is hard-coded twice (`SessionsScreen.cs:100`, `WorktreesScreen.cs:102`) and dispatched a third time in `Program.cs`. Put the classification on the effect with marker interfaces (`ILeavesScreen`, `INavigates`) and give each in-screen effect one handler class (`IEffectHandler<TEffect>`) registered in the composition root. The screen only routes. Adding a key becomes: an effect record, a reducer case and a handler class, with no change to any screen.
- **Outcomes, not sentences:** user-facing English is composed in three layers: reducers (`SessionsView` footers), use cases (`SessionActions` returns strings) and screens (`SessionsScreen.ConfirmAndDelete`). `DeleteOutcome`, `LaunchOutcome` and `WorktreeRemovalOutcome` already point the right way; finish it so use cases return outcome records and one `Wording` presenter turns them into footer text. Wording then has one test file, and the `IsFinal` bug above could not have happened.
- **A folder path value object:** case-insensitive path comparison is re-implemented in `StateStore.SamePath` (line 115), `RepositoryCatalogue.SamePath` (line 40), `WorktreeInventory.Normalise` (line 183), `SessionActions.cs:149`, `WorktreeActions.cs:23` and the `Selected` property at `WorktreesView.cs:48`. A `FolderPath` record with normalised equality replaces all six and gives `RepositoryPath` a home. `JobId`, `SessionId` and `BranchName` wrappers follow, which the object calisthenics rule asks for anyway.
- **Split Session by kind:** `Session.JobId` is nullable and `Kind` says when; five `JobId!` bangs (`SessionActions.cs:57`, `:138`, `:145`, `SessionsView.cs:176`, `:180`) encode the invariant by hand. A sealed `Session` hierarchy with `BackgroundSession` (job id) and `InteractiveSession` (process id) lets pattern matching carry it, and the reducer's `SessionAction` guard shrinks.
- **One worktree inspector:** git-backed facts are gathered three ways: `SessionActions.FactsAsync` (line 223), `WorktreeActions.IsMergedAsync` (line 54) and `WorktreeInventory.InspectedAsync` (line 82). One `WorktreeInspector(IGit)` returning `WorktreeRemovalFacts` serves all three and leaves `RemovalDecision` as the only judge.
- **One tab script factory:** PowerShell is built in `TabOpener.cs:41`, `TrustRecovery.cs:17` and `WorktreeActions.cs:42`, with `claudeExecutable` and `vantageExecutable` plumbed through `TabOpener`, `LaunchWorkflow` and `TrustRecovery`. A `TabScripts` class owning both paths and exposing `Attach(jobId)`, `Trust(directory)` and `Shell()` keeps the rule about never interpolating user text into PowerShell in one tested place.
- **Keep CLI vocabulary out of Domain:** `Domain\DisplayState.cs:33` matches `"busy"`, `"waiting"`, `"idle"`, `"blocked"` and `"done"`, and `SessionListingEntry` is the CLI's shape. Move the mapping to `Adapters.Claude` as an anti-corruption layer so Domain speaks only in `DisplayStateKind`.
- **Split StateStore into five small stores:** behind ports `ITabRegistry`, `IRecentRepositories`, `ICreatedWorktrees`, `ISessionDescriptions` and `IVantageConfig`, sharing a private `JsonFile` helper. Each consumer names the one or two it needs, in-memory fakes replace the temp folders, and the calisthenics limit on instance variables becomes reachable for `SessionActions` (five dependencies today) and `TabOpener` (six).
- **Shrink the constructors:** `SessionsScreen` takes eight constructor arguments. With handlers per effect and the generic screen it needs the definition, the loader and the dispatcher.
- **Later, the wizard as a reducer:** `LaunchWizardDialog.cs` is 282 untested lines of closures. The state-and-input pattern the two views already use (`WizardState`, `WizardInput`, `WizardView.Reduce`) would bring the validation and focus flow under test and leave the dialog as binding code. Worth doing after the split, not before.
- **Small tidies:** `SessionTableSource.Age` is borrowed by `WorktreeTableSource.cs:28`; it is a duration formatter and wants its own home. `LaunchWorkflow` started as a pass-through facade and on `main` has grown a `TabOpener` dependency and a `StartedAsync` method that composes footer sentences, so it is now a third place that owns wording; once `TabScripts` and the handlers exist it can go. `IGit` mixes throw-on-failure (`RunOrThrowAsync`) with null-on-failure methods and the interface does not say which; document it or return a result type consistently.
