# Design

## Context

`CommandLine.Build` declares the root with one description string; System.CommandLine prints it under `Description:` in `vantage --help` and keeps line breaks. Command-line descriptions sit beside their symbols, while every other user-facing word lives in `Wording`. The icon is drawn by `tools\New-Icon.ps1` with System.Drawing; its outputs are committed and a build never runs it. The README is the nuget.org package page, so its images are absolute `raw.githubusercontent.com` URLs on `main` (nuget.org renders images only from trusted hosts, which include that host and `img.shields.io`).

The Buy Me a Coffee cover is shown full width at a fixed height of about 390 px on a 2000 px wide window and cropped at the sides as the window narrows; the About and Support cards overlap its bottom fifth in the middle 1000 px.

## Goals / Non-Goals

**Goals:**
- One spelling of the support URL in code.
- One drawing routine for all three header images, so they never drift apart, regenerated by one script.

**Non-Goals:**
- Any change to the Keys help dialog or other Terminal.Gui code (see proposal.md, out of scope).
- Redrawing the icon: the header calls the same drawing as `New-Icon.ps1`.

## Decisions

- **The support line is a `Wording` fact that `CommandLine` reads.** `Wording.SupportUrl` holds `https://buymeacoffee.com/simonvane` and `Wording.SupportLine` the whole line (`Buy me a sliver of a Claude Max plan: <url>`); the root description is `"A console for Claude Code sessions and git worktrees on Windows.\n" + Wording.SupportLine`. Alternative: a literal in `CommandLine`, as the other descriptions are; rejected because the same URL may later appear in the Keys dialog once it fits, and a fact gets one home.
- **The header reuses the icon's drawing.** `New-Header.ps1` dot-sources nothing from `New-Icon.ps1` (that script writes files when run), so the mark's drawing moves into `tools\VantageMark.ps1`, a function file both scripts dot-source: `Add-VantageMark $graphics $x $y $size`. `New-Icon.ps1` then draws the 512 px master through it, and its outputs must stay byte-identical, which the re-run checks with `git status`. Alternative: draw the header from `vantage-512.png` as a bitmap; rejected because it scales a raster and loses the crisp edges at 3200 px.
- **Layout.** Navy gradient (`#1E1B4B` to `#0F172A`, the icon's own), faint teal and violet branch lines with ring nodes drifting across the background as a git graph, then the mark (rounded tile), `Vantage` in Segoe UI Semibold and the tagline in Cascadia Mono (both ship with Windows 11; the script fails if either is missing rather than silently substituting). `TextRenderingHint` AntiAliasGridFit. One `New-Header` function takes the canvas size and a content box, so each output is a layout, not a copy:
  - Cover, 3200 x 800: mark and words centred in the top 70 %, within the middle 2000 px, so a narrow window's crop keeps them and the cards cover only background.
  - README banner, 1600 x 400 (shown at 800 px wide on GitHub, sharp on high-DPI screens): content centred, full height.
  - Social preview, 1280 x 640: content centred, with the tagline wrapped onto two lines if needed; GitHub keeps 40 px clear at each edge.
- **QR code.** The supplied 1920 px QR is resized to 160 px by the same script's resize helper and committed as `assets\support\buy-me-a-coffee-qr.png`; plain Markdown cannot size an image, and the README already avoids HTML. The source file is not committed.
- **Badge.** `https://img.shields.io/badge/Buy_me_a_sliver_of_a-Claude_Max_plan-FFDD00?logo=buymeacoffee&logoColor=black`, linking to the page, on the line under the banner.

## Risks / Trade-offs

- [README images show as broken links until the pull request is merged, because they point at `main`] → the existing icon already works this way; check the branch's images through GitHub's file view before merging.
- [Moving the mark into a shared function changes `New-Icon.ps1`] → re-run it and require `git status` to show no change under `assets\icon\`.
- [The cover's crop depends on Buy Me a Coffee's layout, which can change] → content sits in the middle 2000 px and the top 70 %, and the owner repositions it with the page's own "drag to reposition" if needed.
