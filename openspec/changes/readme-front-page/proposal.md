# Proposal

## Why

The README is the first thing anyone sees when the repository goes public, and today it reads as a manual: a list of features, a to-do where the screenshot should be, prerequisites before the install, and the "why" and the support link at the very end. A reader should feel the problem Torni solves in the first few lines, see it running, install it in two commands and be using it a minute later, with the detail one link away.

## What Changes

- **A front page, not a manual:** the README is reordered to banner, the problem in two or three sentences, a screenshot, what Torni does, why I built it, support, install, getting started and learn more. Everything else moves to the user guide.
- **The problem first:** the opening names the pain (several Claude Code sessions in a dozen tabs, one of them silently waiting for you) before naming Torni as the answer.
- **A screenshot and a short animation:** a PNG of the Sessions tab in a Windows Terminal window with several coloured session tabs, showing every state, both GitHub and Azure DevOps pull requests, the TAB swatches and the detail pane; and a GIF of a few seconds of starting a session with `n`. Both are committed under `assets\readme`.
- **Made-up names only:** both images show only Northwind.* repositories (and, at most, Torni itself), never a real or work repository, a real person or a real path.
- **Regenerated by a script:** `tools\New-ReadmeScreenshot.ps1` builds the demo repositories and runs `tools\ReadmeScene`, a new tools project that builds Torni's real console screen from the shipped libraries with scripted Claude Code, `gh` and `az` answers and in-memory state, opens the session tabs through Torni's own Windows Terminal adapter, plays the keys for the animation and captures the window. It never touches the owner's Torni state, Claude Code folder or sessions.
- **Install that looks as simple as it is:** `winget install Source191.Torni` first, then the one prerequisite winget cannot bring (Claude Code), then `torni`. The without-winget zip and previews move to the user guide.
- **A brief getting-started guide:** creating a session, seeing the sessions, creating several, finding them all still listed after closing and reopening the terminal (and resuming after a reboot), and the Torni profiles that `torni setup-terminal` adds.
- **A user guide:** a new `docs\user-guide.md` holds the detail the README drops (every key, the columns and the detail pane, notifications and sounds, configuration, `torni here`, without winget, previews, upgrading and uninstalling, privacy), linked from the README's getting started and first in Learn more.
- **Credit for the author:** a "Built by Simon Vane" badge linking to https://www.linkedin.com/in/simonvane/ sits beside the sponsor badge under the banner, and "Why I built it" ends with the same linked name, so readers know who made Torni and where to find him.
- **Support and the story nearer the top:** "Why I built it" moves up beside the screenshot, and "Support Torni" with its QR code follows it, ahead of the install.
- **Support that is easier to give:** a `.github/FUNDING.yml` so GitHub shows a Sponsor button in the repository header; the official Buy Me a Coffee button in place of the shields.io badge; the ask placed under the banner, after the story and at the end of getting started, once the reader has seen Torni work; a specific ask that says the money goes towards the Claude plan Torni is built with; and a mention of monthly memberships for regular users.
- **Docs that point at the guide:** `CLAUDE.md` and `CONTRIBUTING.md` stop calling the README the user guide.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `needs-input-notification`: the requirement that the README has a notifications section naming `torni setup-terminal` becomes the user guide's notifications section, with the README's getting started naming `torni setup-terminal` as the step that sets up the profiles and both bells.

## Out of scope

- **Product changes:** nothing under `src\` changes, so there is no version raise and no release. Hidden overrides for Claude Code's location and the state folder were considered for the screenshot and left out; see the design.
- **Multiple Claude accounts:** a later change (issue #203); neither the README nor the guide mentions them.
- **A documentation site:** no GitHub Pages or wiki; the guide is a Markdown file in the repository.
- **The banner and social preview:** `assets\header` and `tools\New-Header.ps1` stay as they are.
- **Translations:** English only, as `locale.md` says.
- **Recording in CI:** the script needs an unlocked desktop and Windows Terminal, so it is the owner's to run by hand.

## Impact

- **Documentation:** `README.md` rewritten; new `docs\user-guide.md`; `CLAUDE.md` and `CONTRIBUTING.md` lines on where the user guide lives; `openspec\specs\needs-input-notification\spec.md` on archive.
- **GitHub:** new `.github/FUNDING.yml`; the owner turns on monthly memberships in the Buy Me a Coffee account before merging.
- **Assets:** new `assets\readme\sessions.png` and `assets\readme\new-session.gif`, referenced from the README by their raw GitHub URLs as the banner is.
- **Tools:** new `tools\New-ReadmeScreenshot.ps1`, `tools\ReadmeScene` (the scene host, its scene file and key script) and `tools\ReadmeScene.Tests`, added to the solution; `ReadmeScene` references the three `src` libraries, and its tests `test\Source191.Torni.TestDoubles`. The script needs ffmpeg for the GIF.
- **CI:** the new test project runs with the solution's tests; no workflow changes.
- **Depends on:** PR #206 (install-with-winget), whose README this one rewrites; this branch stacks on it.
