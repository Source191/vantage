# Design

## Context

See proposal.md for why. `ProcessRegistry` (330 lines at `main` ac7cdae0) is already `partial` for the `[LibraryImport]` generator. Its reads split two ways: `UsageOf` (`ProcessRegistry.cs:90-115`) opens its own limited handle, reads `GetProcessTimes` (a non-zero exit time reads as gone), `GetProcessMemoryInfo` and the command line through `NtQueryInformationProcess` class 60; `StartTimeOf` and `ParentOf` go through `WithProcess` and `Process.GetProcessById`, with `ParentOf` reading `ProcessBasicInformation` through `process.Handle` and naming the parent by opening it too and reading `ProcessName`. `Terminate` and `EndCleanly` need a `Process` (`Kill(entireProcessTree: true)`, `WaitForExit`). The Windows facts in `.claude\rules\windows.md` record the 20 ms cost of `GetProcessById`, the limited handle's rights and that command lines carry secrets.

Three identity rules guard what is ended, one per file: `ProcessIdentity.StillTheSession` (`Domain\ProcessIdentity.cs:12`, the listed start plus five seconds), `TabRegistration.IsLive` (`TabRegistration.cs:37`, the recorded start exactly; read as a bool by `TabRegistrations.Live` and `OpenTabHandler.cs:59` and beside a shell id by `SessionTabs.cs:18`) and `TerminalTab.StartedNoLaterThan` (`TerminalTab.cs:43`, a parent no younger than its child). `AdoptSessionHandler.cs:26-33` and `CloseEmptyTerminalsHandler.cs:30-37` check the first rule and then pass `session.ProcessId` and `ShellOf`'s `int?` to `Terminate` and `EndCleanly`. `ProcessUsage.CommandLine` is read only by `MemoryBreakdown.cs:19-29`, which reduces it with `ProgramLabel.From(child.Process.Name, commandLine)` at once. `NullFreeModelsShould.Kept` (lines 34 to 40) excuses the registry's three nullable answers, `ProcessIdentity`'s nullable parameter and `TerminalTab`'s two nullable returns; `KeepNoStaleEntry` fails for an excuse whose member is gone.

## Goals / Non-Goals

**Goals:**
- One way to read a process in the adapter; `GetProcessById` only to end one.
- A port that cannot end a process nothing has confirmed, with the three identity rules in one Domain type.
- The command line read, reduced and dropped inside one adapter method.
- Every answer the adapter gives today pinned by `ProcessRegistryIntegrationShould` before it is re-implemented.

**Non-Goals:**
- Changing which processes are ended, when, or what any key reports.
- Moving `IProcessRegistry` out of Domain, or giving process ids a type.

## Decisions

**`ConfirmedProcess` carries its own doors; `ProcessIdentity` is retired.** `public sealed record ConfirmedProcess` in Domain with a private constructor, `int Id` and `DateTimeOffset StartedAt` (the start it was confirmed by), and three static doors, each `bool Try...(..., [NotNullWhen(true)] out ConfirmedProcess? process)`: `TryConfirm(int processId, DateTimeOffset? processStartedAt, DateTimeOffset sessionStartedAt, ...)` with the five-second rounding, `TryConfirmClaim(int processId, DateTimeOffset? processStartedAt, DateTimeOffset claimedStartedAt, ...)` exact, and `TryConfirmParent(int parentId, DateTimeOffset? parentStartedAt, ConfirmedProcess child, ...)` for a parent started no later than its confirmed child. A private constructor is reachable only from the declaring type, so this is the one shape in which "only the check can mint" is enforced by the compiler; it is also the text values' shape (`SessionId.TryParse`). The review named `ProcessIdentity.TryConfirm` and sketched an `internal static Mint`, but `internal` is reachable from every handler in Core, and `ProcessIdentity` cannot call another type's private constructor. Alternatives: the record nested as `ProcessIdentity.Confirmed`, which keeps the class name but reads oddly in the port (`Terminate(ProcessIdentity.Confirmed)`); or `internal Mint` plus a Roslyn text fact over `src` naming its one caller, which is a net where a constructor will do. The nullable `processStartedAt` parameters stay on the `Kept` list with `ProcessIdentity`'s reason ("takes `IProcessRegistry.StartTimeOf`'s answer as it comes"); the `out` is a house shape and needs no entry.

**The port ends only a `ConfirmedProcess`.** `void Terminate(ConfirmedProcess process)` and `void EndCleanly(ConfirmedProcess process)`; the adapter and the fake read `.Id`, and `FakeProcessRegistry.Terminated` and `EndedCleanly` stay `List<int>` so no handler assertion moves. `StartTimeOf`, `ParentOf`, `UsageOf` and `Snapshot` keep `int`: reading an id is harmless. Alternative: a `bool` answer from `Terminate` for "not confirmed", which would still let a caller skip the check.

**`TabRegistration.TryConfirmShell` is the claim's door; `IsLive` is defined by it.** `bool TryConfirmShell(IProcessRegistry processes, out ConfirmedProcess? shell)` answers true only for a claimed tab whose `StartTimeOf` equals the recorded start (through `TryConfirmClaim`); it takes no clock, because only the pending arm needs one, so `IsLive(now, processes)` is `Pending` within its grace period or `TryConfirmShell`. `SessionTabs` ends the shell it answers; `TabRegistrations.Live` and `OpenTabHandler` keep the bool. `OwningTerminal` confirms the claim first and walks from the confirmed shell, so a claimed tab whose id has been reused answers `TerminalWindow.Any` instead of the impostor's window: the registration is pruned as stale on the same refresh, and `Any` only widens the UI Automation search.

**`TerminalTab` walks from a confirmed root and mints each step with `TryConfirmParent`.** `ShellOf(ConfirmedProcess process, IProcessRegistry processes)` answers `ConfirmedProcess?` (the `Kept` entry's reason reworded) and `TerminalOf(ConfirmedProcess process, IProcessRegistry processes)` keeps `int?`, because a terminal is only focused, never ended. The walk no longer re-reads the root's start time (`TerminalTab.cs:21`), the confirmed process carries it. The int overloads are deleted once the handlers have moved. If `fix-removal-paths` has landed, its `ShellAbove` takes the same shape and `CloseEmptyTerminalsHandler`'s `EndCleanly` on claude-as-root passes the confirmed claude.

**One `Opened<T>(int processId, Func<nint, T> query, T whenGone)`.** `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)`; a zero handle answers `whenGone`; `CloseHandle` in `finally`. `StartTimeOf` is `GetProcessTimes` through it, keeping `UsageOf`'s rule that a non-zero exit time reads as gone (`GetProcessById` throws for a process that has exited but is still held open; the new path must answer null for it too). `ParentOf` is `NtQueryInformationProcess(ProcessBasicInformation)` through it, which [limited rights suffice for](https://learn.microsoft.com/windows/win32/api/winternl/nf-winternl-ntqueryinformationprocess), and names the parent through a second `Opened` with [`QueryFullProcessImageNameW`](https://learn.microsoft.com/windows/win32/api/winbase/nf-winbase-queryfullprocessimagenamew) and `Path.GetFileNameWithoutExtension`, the same reduction `Snapshot` applies to `szExeFile`, so `ParentOf` and `Snapshot` name a process identically. Alternative for the name: one `Snapshot()` entry per call, a few milliseconds each and three per walk step, against microseconds for one more limited handle. A parent that refuses a limited handle is answered as null, which changes nothing observable: today the walk reads `StartTimeOf(parent)` next, which fails for the same process and stops the walk there. `UsageOf` is unchanged but for the label. `MeasureTwoHundredTimesWithinASecond` covers `UsageOf` only, so `StartTimeOf` gets its own.

**`WithProcess` keeps only the `Action` form.** After `StartTimeOf` and `ParentOf` move, the `Func<Process, T>` overload has no caller; one `WithProcess(int processId, Action<Process> action)` remains, with `fix-removal-paths`' `AggregateException` catch. The review asked for the `Action` overload to delegate to the generic one, which would leave a generic nobody calls.

**`ProcessRegistryNative.cs` holds the interop.** The constants, structs, `ExecutableName` and every `[LibraryImport]` move to the partial's second file, named as `OneTypePerFileShould` requires (`WordingOfConsole.cs` is the precedent); `nint`/`nuint` replace `IntPtr`/`UIntPtr` (`ToInt64()` becomes a cast, `UIntPtr.ToUInt64()` a cast). `QueryFullProcessImageNameW` is the one new import. The Infrastructure `README.md`'s `AllowUnsafeBlocks` note still holds: the generated code is in the same type.

**The command line is reduced in `UsageOf`, not wrapped.** `ProcessUsage(DateTimeOffset StartedAt, MemorySize PrivateMemory, string Label)`; `UsageOf` reads the name through `QueryFullProcessImageNameW`, calls `ProgramLabel.From(name, CommandLineOf(handle))` and keeps nothing else, so the rule "nothing else is kept, logged or shown" is true of the whole process, not of one method's discipline. `MemoryBreakdown` reads `measured.Usage.Label` for a measured child and keeps `child.Process.Name` for an unmeasured one; its `CommandLineOf` goes. Alternative: a `CommandLineText` wrapper whose `ToString()` is a constant and whose `LabelFor(name)` reduces on demand, which stops accidental printing but keeps the secret in every tree node for the tree's lifetime and relies on each reader calling `LabelFor`. The reduction facts stay in `ProgramLabelShould`; `MemoryBreakdownShould`'s fixtures become labels; `FakeProcessRegistry.Using(processId, startedAt, privateMemory, label)`.

**Order of work.** Domain first (the doors, then the two Domain callers, with the int overloads kept beside the new ones so each commit builds), the adapter next (the file split, then `Opened`, then the label), the port and the three handlers together last (one compile-driven step that deletes the int overloads and `ProcessIdentity`, pinned by the handlers' existing refusal facts such as `reused.Terminated.ShouldBeEmpty()` and by `KeepNoStaleEntry`), each group carrying its own docs.

## Risks / Trade-offs

- [`StartTimeOf` through `FromFileTimeUtc` disagrees with `Process.StartTime.ToUniversalTime()`, which goes file time to local to UTC] → identical to the tick outside a DST ambiguous hour, which `ReportTheStartTimeOfARunningProcessInUtc` pins; a claim recorded by the previous version for a shell started in that hour would read stale once and be pruned, closing nothing.
- [`ProcessBasicInformation` or `QueryFullProcessImageNameW` refuses a limited handle on some process] → `NameThisProcessAsTheParentOfAChildItStarted` and the `pid 4` no-throw fact run against the real table; the refusal reads as gone, as today's walk already stops there.
- [The port retype cascades to the adapter, the fake and three handlers in one step] → the handlers' tests already pin refusal and success by `Terminated` and `EndedCleanly` ids, which do not move; the step is honest about being compile-driven.
- [`ProgramLabel.From` is called from Infrastructure] → Domain from an adapter is the house pattern (`FolderPath.From`); the sleeper fixture changes to `ping.exe` so the real-process fact proves the reduction ran rather than the `cmd` fallback.
- [Three open changes touch the same files] → `fix-removal-paths` first; this change rebases over `ShellAbove` and the catch; `fix-refresh-ordering` and `folder-deleter-and-ports` are folder or file moves only.

## Migration Plan

Nothing to migrate: no state file, key, setting or command line changes. Rollback is reverting the pull request.
