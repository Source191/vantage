# Design

## Context

See proposal.md for why. `Session(SessionId SessionId, string Name, FolderPath WorkingDirectory, DateTimeOffset StartedAt, DisplayState State)` (`src\Source191.Vantage.Core\Domain\Session.cs:8`) is the abstract base of `BackgroundSession` and `InteractiveSession`, both positional records; `ClaudeAgentsListing.ToSession` sets `Name` to `row.Name ?? string.Empty` (`src\Source191.Vantage.Infrastructure\Claude\ClaudeAgentsListing.cs:48`), and `Row.Name` is `string?` (`:73`) because the CLI's JSON leaves the field out for the SDK's automated runs. `SessionName` is an `ITextValue` whose one rule is "not blank", with `From`, `Validate` and `TryParse(string?, [MaybeNullWhen(false)] out SessionName)` (`Domain\SessionName.cs:24-39`). `IClaudeCli` has two `ResumeBackgroundAsync` overloads (`Ports\IClaudeCli.cs:21-25`), `ClaudeCli` a private `ResumeAsync(IReadOnlyList<string> arguments, ...)` they share (`ClaudeCli.cs:56-76`). The name is read as a string by `SessionsScreenDefinition.Cell` (the NAME cell), `WordingOfDetail.Detail(SessionDetail, ...)` (the pane's title), `SessionsViewState` (a filter field at `:23` and the table title's label at `:36`), `TabScripts.Attach` (the tab title, `TabScripts.cs:22-23`) and `OpenTabHandler.SwitchToTabAsync` (the title `FocusTabAsync` looks for, `OpenTabHandler.cs:64`), `DialogEffects` (the rename dialog's prompt and starting text, the delete and close-empty questions, the memory dialog), `WorktreeInventory` (into `WorktreeSession.Running`, then `Domain\RemovalDecision` into `RemovalReason.LiveSession`, and `OpenWorktreeSession`), and by every handler that builds an outcome record or `StatusMessage` naming the session. Main has moved to 8dbf4150 (0.20.0-preview.13) since this was written; the five changes that landed (PRs #175, #177, #178, #179, #180) touched none of these lines, and the fifty readers are the same fifty. `WordingShould`, `WordingOfOutcomesShould` and `StatusTonesShould` build every case by reflection through a `Placeholder(Type)` switch that throws for a type it does not know. The handler tests run the real `ClaudeCli` over `FakeProcessRunner` and assert the `claude` arguments; there is no `FakeClaudeCli`. In every capture in `ClaudeAgentsListingShould`, a session row has a name, the CLI deriving one from the folder (`repos-93`, `Northwind-9d`) when none was given; the only nameless rows are automated runs, which never become sessions.

## Goals / Non-Goals

**Goals:**
- Absence of a listed name is a named case decided once at the boundary, and nothing downstream tests a string for blankness.
- One resume method on the port; the three handlers call it with the session's name as it is.
- Behaviour identical to today for every session, an unnamed one included (blank wherever a name is shown).
- Every step compiles and passes on its own, so the ~36 record members change in reviewable groups.

**Non-Goals:**
- Choosing words for an unnamed session (see the second decision).
- Typing `IClaudeCli`'s ids and directories, or any other port's strings.
- Changing what `fix-cli-contracts` changes in the same methods.

## Decisions

**`ListedName` is a plain two-case record, decided by the adapter.** `public abstract record ListedName` with `Named(SessionName Name)` and `Unnamed` nested inside it, in `Domain\ListedName.cs`, like `JobProcess` and `WaitingReason`. It is not an `ITextValue` (it holds a value or nothing, not text) and has no `From`, `TryParse` or factory: `ClaudeAgentsListing.ToSession` writes `SessionName.TryParse(row.Name, out SessionName? name) ? new ListedName.Named(name) : new ListedName.Unnamed()`, so `SessionName.TryParse`'s "a blank or missing listing name" comment (`SessionName.cs:36`) stays the one rule and the `string?` is met on the line that receives it. Alternative rejected: a `ListedName.FromListing(string?)` in Domain, which fails `NullFreeModelsShould` (a nullable parameter outside the `TryParse` shape; since PR #175 the only Try shape it allows is `[MaybeNullWhen(false)]` on the `out`, which `SessionName.TryParse` already has) and duplicates the rule. A switch over `ListedName` names both cases and its discard arm throws `UnreachableException`, the house rule for a two-case hierarchy; `SealedTypesShould` and `OneTypePerFileShould` already cover the shape.

**An unnamed session is shown as the empty string, by `Wording.Name(ListedName)`.** One member answers `named.Name.Value` or `string.Empty`, with a fact per arm in `WordingShould`, and every cell, sentence, title, dialog field and tab title reads it. Today each of those places shows the raw string, which is blank for an unnamed session, so this is the only rendering that keeps `skip_specs: true` honest. Alternatives: a word such as "(unnamed)" is a visible change for a row that has never been seen, and belongs to a change with a spec delta; a `Words` property on `ListedName` puts user text in Domain, which D-13 already flags for `DisplayState`; deriving the folder name from the row cannot work because outcome records and status messages carry a name and no row, so the table and the status line would disagree. The rename dialog's starting text is the same `Wording.Name`, so an unnamed session's dialog opens empty, as now.

**The typed name travels to `Wording`; the string stops at the edge.** Handlers return outcomes and reducers return status messages that `Wording` words at the last moment (CLAUDE.md, Wording), so the records carry `ListedName`: `AdoptSessionOutcome` (4 cases), `DeleteSessionOutcome` (6), `OpenTabOutcome` (3), `RenameSessionOutcome` (`NoMessages.Name`, `Renamed.OldName`, `Restored.OldName`, `Unsupervised.OldName`), `StopSessionOutcome`, `ResumeNote`'s base, `SkippedSession`, `CloseEmptyTerminalsOutcome`'s `Closed`, `Ended` and `Gone` as `IReadOnlyList<ListedName>`, the nine `StatusMessage` cases (`RunsInOwnTerminal`, `NeverSentAMessage`, `NoMessagesToRename`, `WorkingSoRenameWaits`, `AlreadyUnderVantage`, `WorkingSoAdoptWaits`, `SessionNotListed`, `NothingToMeasure` and `NoPullRequest.RowName`, worded in `WordingOfPullRequests`), `WorktreeSession.Running`, `RemovalReason.LiveSession`, `OpenWorktreeSession` and `MemoryBreakdown.SessionName`. `RenameSessionOutcome.Renamed.NewName` becomes a `SessionName`, since the effect holds one. `Wording.RenamePrompt`, `DeleteSessionQuestion`, `CloseEmptyQuestion` and `MemoryDialogTitle` take the typed name too, so `DialogEffects` passes `session.Name` and never a string. The three `Placeholder` switches gain `ListedName`, `SessionName` and `IReadOnlyList<ListedName>` arms. Alternative rejected: handlers calling `Wording.Name` and keeping `string` members, which moves wording into the handlers and hides which strings were names. Left as strings: `StartSessionOutcome.Name` and `Wording.Here`'s name, which come from a `LaunchPlan`'s `SessionName`, not the listing.

**One `ResumeBackgroundAsync(string sessionId, string directory, ListedName name, CancellationToken)`.** `ClaudeCli` builds `["--bg", "--resume", sessionId, .. NameArguments(name)]`, where `Named` gives `["-n", value]` and `Unnamed` gives `[]`, and keeps the shared `ResumeAsync`. `StartBackgroundAsync` keeps `SessionName`: a start always has a name, and widening it would let an `Unnamed` reach `claude --bg` with no `-n`, which the wizard and `vantage here` never do. Alternative rejected (A-10's smaller fix): an extension method `ResumeUnderListedNameAsync(this IClaudeCli, Session, ...)` over the two overloads, which removes the three copies but keeps the sentinel string and the second overload.

**The tab title and its lookup read the same member.** `TabScripts.Attach` sets `TabLaunch.Title` and `OpenTabHandler.SwitchToTabAsync` passes the title to `FocusTabAsync`; if they rendered an unnamed session differently, Enter would stop finding its open tab. Both call `Wording.Name(session.Name)`, and `OpenTabHandlerShould` asserts that the title searched for equals the title the tab was opened with.

**Filter and title.** `SessionsViewState`'s filter field becomes `FilterText.Of(ListedName)` (the value for `Named`, no field for `Unnamed`), the shape `FilterText.Of(Head)` already has; the table title's label is `Wording.Name(row.Session.Name)`. An empty filter field never matched anything, so the filter behaves as before.

**Staging: bridge, migrate, flip.** Step one adds a computed `public ListedName Listed => SessionName.TryParse(Name, out SessionName? name) ? new ListedName.Named(name) : new ListedName.Unnamed();` on `Session`, green with no caller change (Domain reading Domain). Step two moves readers to `Listed` one area at a time, each area's records and `Wording` arms together, so every commit builds and passes. Step three makes the positional parameter `ListedName Name` on the three records, moves the decision into `ClaudeAgentsListing`, deletes the string and `Listed`, and updates the 13 `new BackgroundSession(` and `new InteractiveSession(` sites and the 7 `with { ... Name = }` sites in the tests to wrap their strings; the three blank-name fixtures become `new ListedName.Unnamed()`: `SessionTestData.Terminal(" ", 4242)` at `AdoptSessionHandlerShould.cs:38`, `with { Name = " " }` at `RenameSessionHandlerShould.cs:77` and `with { SessionId = ..., Name = " " }` at `ResumeSessionsHandlerShould.cs:99`. `ClaudeAgentsListingShould`'s nine `session.Name ==` lookups and `ClaudeContractShould`'s two (`:133` and `ListedAsync` at `:255`) compare against a `Named`. `SessionTestData` gains `Named(string)` so handler facts read `new AdoptSessionOutcome.Moved(Named("repos-31"), ...)`. Alternative rejected: changing the positional parameter first, which touches every reader and every fixture in one commit.

**D-10, the name half only.** The clause "ports keep strings and callers pass `.Value`" that ends `CLAUDE.md:69` (quoted in full in proposal.md; main left it as it was through 0.20.0-preview.13) becomes: a port takes the Domain value where one exists, as `IClaudeCli` does for `SessionName`, `ListedName` and `OpeningPrompt`, and the adapter reads `.Value`; its string `sessionId`, `jobId` and `directory` parameters, `ITranscripts.HasMessages` and the other ports D-10 lists are `folder-deleter-and-ports`' to migrate, with the reflection fact D-10 proposes. Restating the rule here without migrating the strings is deliberate: the two changes would otherwise edit the same interface lines.

**Record the CLI's naming as a fact.** The captures already in the repository show the CLI naming an interactive session from its folder when no name was given; a one-sentence fact, with the capture dates and versions (`repos-93` captured 2026-10-23 on 2.1.309, `Northwind-9d` captured 2026-10-30 on 2.1.314, both recorded in `ClaudeAgentsListingShould`'s summaries at `:11` and `:100`), goes in the CLI facts list in CLAUDE.md and `.claude\rules\claude-code.md`, beside the automated-runs bullet that already notes `claude -p`'s derived `tmp-9d`, so the next reader knows `Unnamed` is a shape the JSON allows rather than a row anyone has seen, and why the NAME column help's "the folder name for an unnamed one" is true without Vantage doing anything.

## Risks / Trade-offs

- [`fix-cli-contracts` edits the same methods: `ResumeBackgroundAsync`'s return type and `ClaudeCli.ResumeAsync`, and the handlers' lines around the resume] → `fix-cli-contracts` lands first; this change rebases, keeping its `ResumeResult` cases and exception and changing only the name parameter and the `-n` arguments. Whichever lands second rebases in any case.
- [About 36 record members and 50 interpolations change type in one pull request] → grouped by area in tasks.md, each group green on its own; no words change, so `WordingShould` and `WordingOfOutcomesShould` pin every sentence through the migration.
- [A reader renders the name through something other than `Wording.Name` and an unnamed session shows differently in two places] → after step three the string is gone, so every rendering is a `switch` or `Wording.Name`; the tab-title fact covers the one pair that must agree, and a grep for `ListedName.Named named` outside `Wording` and `ClaudeCli` is the review check.
- [`Unnamed` is untested against a real CLI, because no capture has a nameless session row] → the adapter fact feeds `ClaudeAgentsListing` a row with no `name` and one with `" "`; the behaviour is the blank today's code shows, so a real one changes nothing a person sees.

## Migration Plan

Nothing to migrate: no state file, key, setting, tab title or command line changes. Rollback is reverting the pull request.
