# Proposal

## Why

The code review of 0.20.0-preview.7 (1 November 2026; D-07, A-10, section 4 item 3) found that `Session.Name` is a bare `string` whose blank means "the listing gave no name" (`src\Source191.Vantage.Core\Domain\Session.cs:8`, `src\Source191.Vantage.Infrastructure\Claude\ClaudeAgentsListing.cs:48`), against CLAUDE.md's "a session's name is a `SessionName`" and its rule that a named case stands where a null or sentinel would. That one sentinel forces two `ResumeBackgroundAsync` overloads on `IClaudeCli` (`src\Source191.Vantage.Core\Ports\IClaudeCli.cs:21-25`, implemented at `src\Source191.Vantage.Infrastructure\Claude\ClaudeCli.cs:56-60`) and the same three-line `SessionName.TryParse` decision, comment included, in `AdoptSessionHandler.cs:34-37`, `RenameSessionHandler.cs:40-43` and `ResumeSessionsHandler.cs:30-33`; a fourth caller would copy it again. The name is also read in fifty places as a string (`[Ss]ession\.Name\b` over `src`, the same fifty at 0.20.0-preview.7 and at 0.20.0-preview.13), so nothing says which of them would show a blank.

## What Changes

- **`ListedName` in Domain:** a closed two-case record, `Named(SessionName Name)` and `Unnamed`, that `Session`, `BackgroundSession` and `InteractiveSession` carry as `Name` instead of the string. The case is decided once, in `ClaudeAgentsListing.ToSession`: a listing row whose `name` is missing or blank is `Unnamed`, anything else `Named` through the existing `SessionName.TryParse`.
- **One resume on the port:** `IClaudeCli.ResumeBackgroundAsync(string sessionId, string directory, ListedName name, CancellationToken)` replaces the two overloads; `ClaudeCli` adds `-n <name>` only for `Named`. `StartBackgroundAsync` keeps its `SessionName`, because a start always has one.
- **The three handlers lose the branch:** adopt, rename and resume pass `session.Name` straight through; the comment "A listed name SessionName refuses is resumed unnamed" goes with it. Rename's own call passes `new ListedName.Named(newName)`.
- **The typed name travels to `Wording`:** the outcome records (`AdoptSessionOutcome`, `DeleteSessionOutcome`, `OpenTabOutcome`, `RenameSessionOutcome`, `StopSessionOutcome`, `ResumeNote`, `SkippedSession`, the three lists in `CloseEmptyTerminalsOutcome`), the nine `StatusMessage` cases that name a session, `WorktreeSession.Running`, `RemovalReason.LiveSession`, `OpenWorktreeSession` and `MemoryBreakdown` carry a `ListedName`; `RenameSessionOutcome.Renamed.NewName` becomes a `SessionName`. `Wording` gains one `Name(ListedName)` that every sentence, cell, title, dialog field and tab title reads: the `SessionName`'s value for `Named`, and for `Unnamed` the empty string every one of those places shows today. design.md says why not a word, and why not the folder name.
- **The tab title and its lookup agree:** `TabScripts.Attach` titles the tab and `OpenTabHandler` finds it by title; both read `Wording.Name`, with a fact that pins them together.
- **Staged so every step is green:** `Session` first gains a computed `ListedName Listed` beside the string, readers move to it one area at a time, then the string goes and `Listed` becomes `Name`.
- **CLAUDE.md:** the sentence at `CLAUDE.md:69` in "Values, sessions and null", today "Values that look like strings are types: folders are `FolderPath` (the only place two paths are compared), ids are `SessionId`, `JobId` and `BranchName`, a session's name is a `SessionName` and its worktree part a `WorktreeSlug`, and a tab's owner is a `TabOwner`; ports keep strings and callers pass `.Value`." (unchanged by main up to 0.20.0-preview.13), is restated for `IClaudeCli`'s name parameters only: a port takes the Domain value where one exists (`SessionName`, `ListedName`, as `OpeningPrompt` already does) and the adapter reads `.Value`; the string `sessionId`, `jobId` and `directory` parameters are left for the `folder-deleter-and-ports` change, which owns D-10's id and folder half. "A session's name is a `SessionName`" becomes "a session's listed name is a `ListedName`, `Named(SessionName)` or `Unnamed`". The Claude Code facts in CLAUDE.md and `.claude\rules\claude-code.md` record what the captures in `ClaudeAgentsListingShould` already show: the CLI itself names a session started without `-n` after its folder (`repos-93`, captured 2026-10-23 on 2.1.309; `Northwind-9d` for `claude -p`, captured 2026-10-30 on 2.1.314), so a session row with no name has not been seen; only the SDK's automated runs, which are never rows, lack one. The sentence sits beside the automated-runs bullet, which already notes `claude -p`'s derived `tmp-9d`.
- **Version and changelog:** `Version` one preview step above `main` when implemented (0.20.0-preview.14 if nothing lands first; a refactor, so patch-level under semantic versioning), and one line under Unreleased in `CHANGELOG.md`, under Internal, which `Assert-ChangelogUpdated.ps1` requires of every pull request that changes the packaged tool: "A session's listed name is a typed value, named or unnamed, decided once as the listing is parsed, and the Claude CLI port has one resume method (#N)", with the pull request's number once it is open.
- `skip_specs: true`: no key, screen, message, tab title, state file or command line behaves differently; an unnamed session shows the same blank it shows today.

## Out of scope

- Giving an unnamed session words or its folder name on screen: a behaviour change for its own change, with a spec delta.
- `IClaudeCli`'s string `sessionId`, `jobId` and `directory` parameters, `ITranscripts.HasMessages` and the other ports D-10 lists: `folder-deleter-and-ports`.
- `StartSessionOutcome.Name` and `Wording.Here`'s name, which come from a `LaunchPlan`'s `SessionName`, never from the listing.
- The `ResumeResult` hierarchy and the adapter's failure convention: `fix-cli-contracts`.
- Multiple Claude accounts, which is a later change.
