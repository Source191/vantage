# Design

## Context

See proposal.md. The sessions table is built by `SessionRowEnricher`, which asks git about each working directory and caches the answer for 30 seconds; its `Location` keeps the repository's name only, not its path. The worktrees table is built by `WorktreeInventory`, whose `WorktreeRow` already carries the owning repository as a `FolderPath`. Both tables refresh on a timer (5 s and 15 s) through `TableScreen.TriggerLoad`, which runs the load off the UI thread and applies the rows with `app.Invoke`. `IGit` puts queries that can fail as nullable answers. `ProcessRunner` starts children with `UseShellExecute = false`, so a bare `gh` resolves through PATH (it is an `.exe`) but a bare `az` does not (it is `az.cmd`). Measured on this machine: one `gh pr list` call about 1.8 s, one `az repos pr list` call about 4.2 s. The worktrees view already uses `p` for prune.

## Goals / Non-Goals

**Goals:** the PR column and the `p` key in both views, from at most one call per repository per three minutes, with no refresh ever waiting on a host; every reason for a blank column reaches the footer as a fact `Wording` can say.

**Non-Goals:** a background timer of its own (lookups ride on the existing refreshes); a pull request cache that survives a restart; per-cell colours.

## Decisions

- **Domain owns the remote parser and the matching rule.** `RemoteRepository.Parse(string? url)` returns `GitHubRepository(Owner, Name)`, `AzureDevOpsRepository(Organisation, Project, Name)` or null. GitHub: `https://github.com/{o}/{r}[.git]`, `git@github.com:{o}/{r}[.git]`, `ssh://git@github.com/{o}/{r}[.git]`. Azure DevOps: `https://[{user}@]dev.azure.com/{org}/{project}/_git/{repo}`, `https://{org}.visualstudio.com[/DefaultCollection]/{project}/_git/{repo}`, `git@ssh.dev.azure.com:v3/{org}/{project}/{repo}`, and `{org}@vs-ssh.visualstudio.com:v3/{org}/{project}/{repo}` (the visualstudio.com SSH form, same shape as the dev.azure.com one). Path segments are URL-decoded (`Northwind%20Trading`). An Azure DevOps name outside `[A-Za-z0-9 ._-]` makes the whole remote null, because `az` is a `.cmd` that cmd.exe parses (see below). `PullRequest(PullRequestHost Host, int Number, Uri Url, PullRequestState State, DateTimeOffset CreatedAt)` with `PullRequestState` a closed enum (`Open`, `Draft`, `Merged`, `Closed`, `Active`, `Completed`, `Abandoned`) and `IsOpen` true for open, draft and active. `PullRequests.ForBranch(IReadOnlyList<PullRequest> forBranch)` picks the open one, else the most recent by `CreatedAt`. The cell words ("#123 open", "!4521 active") live in `Wording`, per the rule that user-facing text lives there.
- **The answer is a lookup fact, not a nullable.** `PullRequestLookup` is `Found(PullRequest)` or `Missing(PullRequestGap Gap)`, with `PullRequestGap` a closed enum: `NoBranch`, `NoRemote`, `UnknownHost`, `CliMissing`, `NotSignedIn`, `Looking`, `Failed`, `NoPullRequest`. The reducer turns a `Missing` into `Footer.NoPullRequest(string RowName, PullRequestGap Gap, PullRequestHost? Host)`, and `Wording` names the CLI from the host ("the GitHub CLI (gh)", "the Azure CLI (az) with the azure-devops extension"). A switch over the gap names every member, so a new gap fails the build at each place that must learn it (CS8509).
- **One port, two adapters, chosen by the parsed remote.** `IPullRequests.ListAsync(RemoteRepository repository, FolderPath checkout, CancellationToken)` returns `PullRequestListing`: `Listed(IReadOnlyList<(BranchName Branch, PullRequest PullRequest)>)` or `Unavailable(PullRequestGap)`. `PullRequestHosts` in Adapters dispatches on the record type to `GitHubPullRequests` or `AzureDevOpsPullRequests`. GitHub runs `gh pr list --repo {owner}/{name} --state all --limit 100 --json number,url,state,isDraft,headRefName,createdAt` in the checkout; `--repo` keeps a fork from listing its upstream. Azure DevOps runs `az repos pr list --org https://dev.azure.com/{org} --project {project} --repository {name} --status all --top 100 --output json` and maps `pullRequestId`, `status`, `isDraft`, `sourceRefName` (dropping `refs/heads/`), `creationDate`, and builds the URL as `{repository.webUrl}/pullrequest/{id}`. The adapters read each CLI's words for "not signed in" (gh's exit code 4 and its `gh auth login` hint; az's `az login` or `az devops login` hint) and for "extension missing", the same way `ClaudeStates` owns Claude's words. Alternative considered: Azure DevOps and GitHub REST calls with a token. Rejected: Vantage would have to store a credential, and both CLIs already hold the user's sign-in.
- **`az.cmd` is found, not guessed.** The Azure adapter looks for `az.cmd` on PATH (as `ClaudeExecutable.Locate` looks for `claude.cmd`) and runs that full path; a missing file is `CliMissing`, and so is a `Win32Exception` from starting `gh`. CreateProcess hands a `.cmd` to cmd.exe, which reads `&`, `|`, `<`, `>`, `^` and `%` in its arguments; the Domain allowlist on Azure DevOps names, and the fixed literal flags, keep every argument free of them. Alternative considered: run az's bundled `python.exe -IBm azure.cli` directly. Rejected: it depends on the install layout.
- **A catalogue in Application caches per repository and never blocks.** `PullRequestCatalogue(IGit git, IPullRequests hosts, TimeProvider clock)` holds, per main checkout `FolderPath`, the parsed remote, the last listing and when it was taken, and the running call if any (a `ConcurrentDictionary`, because refreshes overlap). `Find(FolderPath checkout, BranchName? branch)` is synchronous and answers from the cache only (`Looking` before the first answer). `RefreshStaleAsync(IEnumerable<FolderPath> checkouts)` starts a call for each checkout whose answer is older than three minutes and has none running, and keeps the old answer until the new one lands; a failed or unavailable listing is cached for the same window, so a signed-out CLI is not asked every five seconds. The enricher and the inventory call `Find` for each row and start `RefreshStaleAsync` without awaiting it; tests await it directly. Alternative considered: a separate `PullRequestsLoaded` view input merged into state. Rejected: it adds a second load path to `TableScreen` and both reducers for no gain, since a refresh comes every 5 or 15 seconds anyway.
- **Rows carry the lookup.** `SessionRow` and `WorktreeRow` gain `PullRequestLookup PullRequest`. `SessionRowEnricher.Location` keeps the main checkout's `FolderPath` beside its name (git already returns it), so the catalogue has a path to run git and the CLI in. A session outside a repository, a detached head and every leftover row (orphan, broken, empty) get `Missing(NoBranch)` or `Missing(NoRemote)` without a call.
- **`p` in both views, prune moves to `P`.** `SessionsView` and `WorktreesView` gain a `p` case: no selection gives `NoSessionSelected` or `NoWorktreeSelected`; `Missing` gives `Footer.NoPullRequest`; `Found` gives the background effect `OpenPullRequest(PullRequest)`. `OpenPullRequestHandler` opens `PullRequest.Url` through `IDesktop.OpenAsync`, which `folder-column-and-open-keys` adds and returns `OpenPullRequestOutcome(PullRequestHost, int Number)`. Prune's `p` becomes `P` in `WorktreesView`. Alternative considered: a different letter for the pull request in the worktrees view. Rejected: one meaning per letter across views is easier to remember than keeping prune's letter, and prune is a repository-wide action like the other capital keys.
- **Columns.** PR follows BRANCH in both tables: NAME, STATE, REPOSITORY, FOLDER, BRANCH, PR, AGE, TAB and REPOSITORY, FOLDER, BRANCH, PR, DIRTY, UNPUSHED, LAST COMMIT, SESSION, HEALTH. The cell is `Wording.PullRequestCell(lookup)`: the number and state for `Found`, empty otherwise.

## Risks / Trade-offs

- [A branch whose only pull request is older than the newest 100 in its repository shows blank] → accepted; such a branch is long finished, and the footer on `p` says no pull request was found rather than claiming there is none ever.
- [The first `w` after start shows blank PR cells for up to one lookup] → the column fills on the next 15 s rescan; the footer on `p` says it is still looking.
- [CLI wording for "not signed in" changes between versions] → the adapters fall back to `Failed`, which the footer still explains, and the adapter tests pin the current words.
- [`az` without the azure-devops extension answers with an install prompt] → read as `CliMissing`, and the footer names the extension.
- [A repository moved hosts while Vantage runs] → the remote is re-read with each refresh of the cache, every three minutes.

## Migration Plan

None for state: nothing is stored. Users of the worktrees view's `p` for prune press `P`; the README, help and key hints say so, and the version rises by a minor step (pre-1.0, so a key change is allowed in a minor).

## Dependencies on other changes

- Needs `folder-column-and-open-keys` merged first: it adds `IDesktop`, whose `OpenAsync` this change's handler uses, the FOLDER column the column lists above assume, and the key-hint column the `p` hint joins.
- `header-and-help` and `remove-session-descriptions` change the help text and the sessions columns; if either is archived after this change is written, rebase the help glossary entry and the column list on what `main` then has. This change modifies no existing requirement text, so no delta needs rebasing.
