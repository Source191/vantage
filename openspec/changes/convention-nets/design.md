# Design

## Context

See proposal.md for why. The root `Directory.Build.props` turns on the .NET analysers at `10.0-recommended`, `EnforceCodeStyleInBuild`, `TreatWarningsAsErrors` and SonarAnalyzer for every project under the repository, tests and `tools\HeadlessTerminal` included; no project references `Microsoft.CodeAnalysis.BannedApiAnalyzers`. The reflection facts live in `test\Source191.Vantage.Core.Tests\Architecture` over NetArchTest and `System.Reflection`; the one source-text fact, `OneTypePerFileShould`, lives in `test\Source191.Vantage.Infrastructure.Tests` because only that project references `Microsoft.CodeAnalysis.CSharp` and has `RepositoryFolder.Root()` (its README says so). The seven reducers are already `static class`es; `ConsoleView` holds one `static readonly HashSet<Type>`. `TabKeys.TryFor` is the Application-side rule for the tab keys; `TableBody.ScrollStep` (`TableBody.cs:389-393`, private) is the Tui-side rule for `<` and `>`. `KeyHelp.Key` is text: `enter`, `esc`, `←`, `→` or one character. `DiagnosticEvent` is an abstract record with top-level cases, so a test can derive a probe from it. Today's uses that a banned list would hit (re-checked at main 8dbf4150, 0.20.0-preview.13): `Thread.Sleep(SettleTime)` at `ConsoleRecovery.cs:52`, `Task.Run(...).GetAwaiter().GetResult()` at `LaunchWizardDialog.cs:27`, `UseShellExecute = false` at `ProcessRunner.cs:56`, and `Process.Start(startInfo)` at `Desktop.cs:57`, which takes a `ProcessStartInfo` and is not a `string` overload. The `.Result` reads at `LaunchWizardDialog.cs:88, 90`, `ProblemReportDialog.cs:59` and `SettingsDialog.cs:154-157` are Terminal.Gui's `TextChangingEventArgs.Result`, which the id ``P:System.Threading.Tasks.Task`1.Result`` does not match, so they are not exemption candidates. The tool project's `Composition` folder (`ConsoleComposition`, `HereComposition`, `LaunchParts`, `SharedParts`, `TerminalSetupComposition`, PR #177) and `Program.cs` use nothing on the list; nothing from PR #179 appears in the banned grep (`PeriodicCounts.cs:23` uses `TimeProvider.CreateTimer`). `catch (ArgumentException` appears in `ClaudeSettings.cs:78` and `ProcessRegistry.cs:185, 209`. The `volatile` keyword appears once, `SharedSnapshot.cs:16`, and the word once more in that file's doc comment. Primary-constructor parameters guarded with `?? throw new ArgumentNullException` number 33 initialisers in 17 files (`SessionDetails`, `WorktreeDetails`, `CurrentSettings`, `LatestSessions`, `SharedSnapshot`, `NuGetPackageVersions`, `ConfigScreenDefinition`, `ConsoleScreen`, and since 0.20.0-preview.8 `ConsoleLoads`, `HeaderSettingsRow`, `UpdateCheckSwitch` (PR #177), `EditorPresets` (PR #178), `Heartbeat`, `RefreshCounts` (PR #179), `WhatsNewOnStart`, `PackagedReleaseNotes` (PR #180)), plus the two `KeyOf` bodies in `SessionDetails.cs:13` and `WorktreeDetails.cs:14`; 98 `ThrowIfNull` calls sit in 51 files; most public methods guard nothing. The key bar's click already maps a key's text to a `Key` (`ConsoleScreen.cs:593-598`), the mapping the parity fact mirrors on the Application side.

## Goals / Non-Goals

**Goals:**
- Every rule the review marked "not enforced" that can be held by an analyser or a fact is held by one, failing the build or the fast suite.
- Each new fact is red once before it is green: for a fact that holds today, by a deliberate probe that is then removed.
- No behaviour changes: no key, message, state file or command line differs.

**Non-Goals:**
- Enforcing "user text only in `Wording`" (owner's call, `wording-one-home`), "never a bare program name" (I-03) or the two-case discard rule by a Roslyn switch walker (the review judged it of doubtful value; the facts here close the three known slips instead).
- Reaching `tools\HeadlessTerminal` with the banned list or `SealedTypesShould`.

## Decisions

**The banned list is scoped by `src\Directory.Build.props`, not by four project edits.** MSBuild stops at the first `Directory.Build.props` it finds walking up, so a file in `src` replaces the root's unless it imports it: the new file's first element is `<Import Project="$([MSBuild]::GetPathOfFileAbove('Directory.Build.props', '$(MSBuildThisFileDirectory)../'))" />`, then one `PackageReference` (`Microsoft.CodeAnalysis.BannedApiAnalyzers` 5.6.0, `PrivateAssets="all"`) and one `<AdditionalFiles Include="$(MSBuildThisFileDirectory)BannedSymbols.txt" />`. A `.globalconfig` was considered and rejected: it can set severities but cannot add a package or an additional file, so the real alternative is the same two lines in four `.csproj` files, which a fifth `src` project would miss. The new props file keeps comments beside its settings as the root one does; CLAUDE.md's comment rule (line 30) and `CONTRIBUTING.md:99` say "the two `Directory.Build.props` files" (owner to confirm).

**Entries name each overload, because a bare method id matches only the parameterless one.** The analyser resolves each line with Roslyn's `DocumentationCommentId`, whose `AllParametersMatch` compares parameter counts, so `M:System.Threading.Thread.Sleep` would match nothing. The file (one `;` reason per line, naming the house rule):
- `P:System.DateTime.Now`, `P:System.DateTime.UtcNow`, `P:System.DateTime.Today`, `P:System.DateTimeOffset.Now`, `P:System.DateTimeOffset.UtcNow`: TimeProvider.
- `M:System.DateTimeOffset.ToOffset(System.TimeSpan)`: `TimeZoneInfo.ConvertTime` with the caller's zone.
- `M:System.Threading.Thread.Sleep(System.Int32)`, `M:System.Threading.Thread.Sleep(System.TimeSpan)`, `M:System.Threading.Tasks.Task.Wait` and its `(System.Int32)`, `(System.TimeSpan)`, `(System.Threading.CancellationToken)`, `(System.Int32,System.Threading.CancellationToken)`, `(System.TimeSpan,System.Threading.CancellationToken)` overloads, ``P:System.Threading.Tasks.Task`1.Result``, `M:System.Runtime.CompilerServices.TaskAwaiter.GetResult`, ``M:System.Runtime.CompilerServices.TaskAwaiter`1.GetResult``: async throughout; `await` lowers in the compiler and is not an invocation the analyser sees, so only a written `GetAwaiter().GetResult()` is caught.
- `T:System.Threading.Volatile`: `SharedSnapshot<T>`.
- `M:System.Diagnostics.Process.Start(System.String)`, `(System.String,System.String)`, `(System.String,System.Collections.Generic.IEnumerable{System.String})`, `(System.String,System.String,System.String,System.Security.SecureString,System.String)`, `(System.String,System.String,System.String,System.String,System.Security.SecureString,System.String)`: a program is run by its located full path through `ProcessRunner`.
- `M:System.String.ToLower`, `M:System.String.ToUpper`: `ToUpperInvariant` or an ordinal comparison (CA1311 already flags these; the line states the rule in the file that states the others).
`ProcessStartInfo.UseShellExecute` is not banned: its one use is `= false` at `ProcessRunner.cs:56`, the safe value, and a property cannot be banned for one value; the ShellExecute route is already closed by `LayeringShould` (`Process` only in Adapters) and `Desktop`'s pwsh child (`windows.md`). The brief listed it; this is the one departure, for the owner to confirm. `Regex` is not banned, as the review asked.

**Two exemptions, each a `#pragma warning disable RS0030` with its reason on the line, restored after.** `ConsoleRecovery.AfterChildProcess` is synchronous by design (it runs between a child's exit and the console's next read, with no caller to await) and its 50 ms settle is the fact `terminal-gui.md` records; `LaunchWizardDialog.Show` blocks on a `Task.Run` because Terminal.Gui's synchronisation context would deadlock an await on the UI thread, as its comment says. A third exemption is a review question, not a pragma.

**Reflection facts stay in `Core.Tests\Architecture`; source-text facts go beside `OneTypePerFileShould`.** `ReducersShould` scans `typeof(SessionsView).Assembly` for types in `Source191.Vantage.Application.Views` whose name ends in `View`, asserts at least seven, and that each is `IsAbstract && IsSealed` (a static class) with every field `IsStatic && IsInitOnly`; the states that carry `IFolders` and a `Func<string, bool>` (V-14) are outside the fact and recorded in CLAUDE.md as the allowed exception. `HandlersShould` pairs every non-abstract type implementing `IEffectHandler<>` with a `<Name>Should` type in Core.Tests (22 handlers at main 8dbf4150, all in `Application\Actions`; `OpenReleasePageHandler` from PR #180 already has its `OpenReleasePageHandlerShould`). `SourceConventionsShould` parses every `.cs` under `src` with the same `CSharpParseOptions` as `OneTypePerFileShould`, through a `SourceFiles` helper that takes a root (`OneTypePerFileShould` walks `src`, `test` and `tools`; these facts pass `src`), and walks syntax, not text: `PostfixUnaryExpressionSyntax` of kind `SuppressNullableWarningExpression` for `!` (a text match would count `!=` and `!123` in a sentence); `SyntaxKind.VolatileKeyword` tokens for `volatile` (a text match would count the doc comment); `CatchDeclarationSyntax` whose type is `ArgumentException`; and string-literal and interpolated-text tokens of `Wording*.cs` and `CommandLine.cs` against the American list, whole word and case-insensitive: color, colors, colored, behavior, center, centered, canceled, favorite, gray, initialize, initialized, organize, analyze, catalog, normalize, recognize, customize, disk. Left off on purpose: dialog (the house word), license (a verb in British English), program. Alternatives rejected: a text grep (the false matches above) and a Roslyn analyser project (a build step for four facts).

**`KeyHelpParityShould` maps the help text to a `Key` and asks the reducer.** `enter`, `esc`, `←` and `→` map to the `Key` statics, one character to `Key.Of`; a key is answered when `TabKeys.TryFor` or `ScrollKeys.TryFor` answers, or when the view's `Reduce` on a loaded state with a selected row returns a state that differs from the input or a non-empty `Effects` list (the `/` key changes only the state, so "effect or message" alone would fail it). The loaded states are built as the view tests build theirs (`SessionTestData` rows, a `WorktreeRowsLoaded` list with a clean row selected, `ConfigRows.For(TestSettings..., facts)`). The reverse direction (a key the reducer handles but the help omits) is not attempted: the handled keys are pattern arms, not data.

**`ScrollKeys` moves the scroll rule into `Application\Views` beside `TabKeys`.** `public static bool TryFor(Key key, out int step)` answers -1 for `<` and 1 for `>`; `TableBody.cs:177` calls it in place of the private `ScrollStep`. Alternative rejected: an `internal` `ScrollStep` tested through `InternalsVisibleTo`, which would leave the console's one key rule outside Application while `TabKeys` is inside it.

**The discard arms become `throw new UnreachableException()` without new tests.** The hierarchies are closed, so no test can reach the arm; the change is a refactor commit each, kept honest by the existing facts (`SessionsViewShould`, `WorktreesViewShould`, `PullRequestCatalogueShould`, `SetupFactsReaderShould`'s `Missing` and `Unset` cases, `JsonFileStoreShould`'s tab-file round trips). `DiagnosticLine` is the exception: a test-local `private sealed record Unknown : DiagnosticEvent` reaches its discard (`DiagnosticLine.cs:59`), so `RefuseAnEventItDoesNotKnow` is a real red. `RenderEveryEvent` covers the eleven events at main (PR #179 added `RefreshSlow(RefreshPart, TimeSpan)` and `UiThreadStalled(TimeSpan)`, PR #180 `PackagedNotesUnreadable(ToolVersion)`); every constructor parameter type is an enum, a nullable, or one of `DiagnosticEventsShould.AllowedTypes`, so the placeholder list in task 4.1 needs no new entry.

**Guard rule: CA1062 everywhere is the mechanical option; the owner has not decided.** Enabling `dotnet_diagnostic.CA1062.severity = warning` in the root `.editorconfig` beside CA1510 to CA1513, with `dotnet_code_quality.CA1062.exclude_extension_method_this_parameter = true`, makes every externally visible method that dereferences a reference parameter guard it, including every reducer's `Reduce`, every `Wording` member and every handler's `HandleAsync`: an estimated several hundred `ThrowIfNull` lines, and whether the rule reaches a primary-constructor parameter captured by a field initialiser is verified in its first task (if it does not, constructors stay convention and the `?? throw` initialiser stays the pattern). The alternative, guard nothing inside the solution: remove the 33 `?? throw` initialisers and the `ThrowIfNull`s whose caller is Vantage's own code, keep guards only where null arrives from outside (JSON, Terminal.Gui, System.CommandLine, the nullable ports), and let nullable reference types carry the rest; cheaper, and consistent with "null is met only on the line that receives it from outside". Since this change was written (ten initialisers in eight files at ac7cdae0), PRs #177 to #180 added 23 more in the house pattern, so the alternative now removes code every change since 0.20.0-preview.8 wrote: a cost for the owner to weigh, not a changed decision. Either way CLAUDE.md line 47 states when, not only how. The proposal flags this as the decision to confirm before group 8 starts.

## Risks / Trade-offs

- [`src\Directory.Build.props` silently replaces the root file if the import is wrong] → the import is the first element, and task 1.1's probe (`DateTime.Now` in a `src` file fails with RS0030 while a test file does not) also proves the root's `TreatWarningsAsErrors` still reaches `src`.
- [A banned-symbol id is misspelt and bans nothing] → each id is probed in task 1.2 by a temporary use that must fail; `RS0031` (an unresolved or duplicate entry) is itself a warning and so an error.
- [`RenderEveryEvent` needs a placeholder per constructor parameter type] → the same `Placeholder(Type)` shape as `WordingShould.cs:36`; a new type fails the fact with "needs a placeholder", as it does there.
- [`KeyHelpParityShould` passes for a key that only clears a message] → a loaded state with a selected row and `StatusMessage.None` is the input, so only a real change or effect counts.
- [Three open changes touch the same files] → `sessions-row-action` and `table-body-collaborators` rebase onto or over this (one-line arms and a two-line call); nothing here depends on their shape.
- [CA1062, if chosen, adds noise to every diff for a while] → it is one group, after the owner's decision, in its own commits.

## Migration Plan

Nothing to migrate: no state file, key, setting or command line changes. Rollback is reverting the pull request.
