# Design

## Context

See proposal.md for why. At `main` ac7cdae0 (0.20.0-preview.8): `IFolders` (`src\Source191.Vantage.Core\Ports\IFolders.cs:9-34`) has eight members and nineteen files name it (thirteen in `Application`, four in `Adapters`, two in `Tui`); `DeleteTree` is called once, at `Application\Actions\WorktreeRemover.cs:70`, and `WorktreeRemover` uses `folders` for nothing else. `RemoveWorktreeHandler.cs:17` and `DeleteSessionHandler.cs:15` each build their own `WorktreeRemover` from the `IFolders` they were given, and `Program.cs:149` builds both handlers for `DialogEffects`. `IProcessRegistry` (`Domain\IProcessRegistry.cs`) is read by `TabRegistration.IsLive` and `OwningTerminal`, `TabRegistrations.Live` and `TerminalTab.Walk` (both `StartTimeOf` and `ParentOf`), from eight `Application` call sites and about twenty-four facts in `TabRegistrationShould` and `TerminalTabShould`; `Settings.Validate(SettingsText, Func<string, bool>)` and `ProcessTree.Under(int, IReadOnlyList<ProcessFacts>, Func<int, ProcessUsage?>)` take functions, and `NullFreeModelsShould.Kept` already excuses the three nullable answers of `IProcessRegistry` and the `usageOf` function. Every caller of `IClaudeCli`, `ITranscripts` and `IWorktreeIncludeCopier` passes `.Value` of a `JobId`, `SessionId` or `FolderPath` it already holds (`Session.SessionId`, `Session.WorkingDirectory`, `BackgroundSession.JobId`, `LaunchPlan.Directory`); the handler facts use the real `ClaudeCli` over `FakeProcessRunner`, so no Claude CLI fake exists. `JsonFileStore.RecentFile(string)` (`:112`) keys on `ToUpperInvariant()`; `JsonFileStore.Options` already carries `TextValueJsonConverter<FolderPath>`, which writes the plain string and reads it back through `TryParse`. `ClaudeExecutable.Locate(IFolders, IReadOnlyList<string>, string)` (`:33-35`) searches the given folders for `claude.cmd` and `claude.bat` unfiltered. `Desktop.OpenAsync` throws `InvalidOperationException` in two places; `OpenProblemReportHandler.cs:28` catches that type, `OpenPullRequestHandler.cs:12` and `OpenSolutionHandler.cs:12` catch nothing, and `TableBody.cs:214` turns any handler exception into `StatusMessage.Failed(message)`. The open change `editor-not-found` adds `ProgramNotStartedException` (thrown by `StartAsync`) and `NoApplicationException` (thrown by `OpenAsync` on exit code 2) beside `IDesktop`.

## Goals / Non-Goals

**Goals:**
- Each of the six rules is held by a fact or by a type, not by a sentence.
- No key, message, file or command line behaves differently; the recent-repositories file keeps its format.

**Non-Goals:**
- Migrating `IGit` or `IFolders` to Domain values, or adding Domain values that do not exist yet (a file path, a package id).
- Changing which failures `OpenPullRequestHandler` and `OpenSolutionHandler` turn into outcomes.

## Decisions

### `WorktreeRemover` takes `IFolderDeleter` alone, and the two handlers take the remover
`IFolderDeleter { void DeleteTree(string path); }` keeps `IFolders.DeleteTree`'s doc (a missing folder is not an error; a root or a relative path is refused). `Folders : IFolders, IFolderDeleter` and `FakeFolders : IFolders, IFolderDeleter`, so no second adapter or fake. `WorktreeRemover(IGit, ICreatedWorktrees, IFolderDeleter, CurrentSettings)`: its root check uses `FolderPath` and the settings, not the disc. `RemoveWorktreeHandler(IGit, ICreatedWorktrees, IFolders, CurrentSettings, WorktreeRemover)` and `DeleteSessionHandler(IClaudeCli, IGit, ICreatedWorktrees, SessionTabs, IFolders, CurrentSettings, WorktreeRemover)` drop their private `remover` fields; the composition builds one `WorktreeRemover` and hands it to both, as `SessionTabs` and `OpenTabHandler` are already shared. The fact, `LayeringShould.HandTheFolderDeleterOnlyToWorktreeRemover`, asks NetArchTest for every type in Core, Infrastructure, Tui and TestDoubles that depends on `IFolderDeleter` and expects exactly `WorktreeRemover`, `Folders` and `FakeFolders`; a new consumer fails it by name. Alternative: the two handlers take `IFolderDeleter` and pass it on, which puts the deleter in three types and needs an allow-list; rejected. `EffectPorts` does not gain the deleter: no dispatcher handler deletes.

### `IProcessRegistry` stays in `Domain`, held by a fact
Chosen over moving it to `Ports` and passing `Func<int, DateTimeOffset?> startTimeOf` and `Func<int, ProcessParent?> parentOf`. Three reasons: the move would add eight nullable-in-generic parameters (`IsLive`, `OwningTerminal` x2, `Live`, `ShellOf` x2, `TerminalOf` x2) to `NullFreeModelsShould.Kept`, where today three members and one function are excused, against the house rule that each nullable is argued for; the two Domain rules read two members together, so a pair of functions is a worse signature than the interface, where `Settings.Validate` reads one; and `process-registry-one-path` is reshaping the same interface (`ConfirmedProcess`), so a move now would be redone. The fact, `LayeringShould.DeclareNoDomainInterfaceButTheTwoNamed`, lists `ITextValue<>` and `IProcessRegistry` with the reason "the process table the tab rules read; implemented in Adapters, faked in TestDoubles" and fails for any other interface in `Source191.Vantage.Domain`. `CLAUDE.md`'s layers line gains "and `IProcessRegistry`, the one boundary interface its rules read (`LayeringShould`)". Alternative (a) stays available: if the owner prefers it, the Kept entries are the cost, and the fact becomes "no interface but `ITextValue<>`".

### The rule is the better half, and a fact names the parameters it covers
"A port takes the Domain value where one exists; adapters read `.Value`." `IClaudeCli.StartBackgroundAsync(FolderPath directory, ...)`, `AttachAsync(JobId)`, `StopAsync(JobId)`, `RemoveAsync(JobId)`, `ResumeBackgroundAsync(SessionId sessionId, FolderPath directory, ...)` (both overloads, or the one `listed-name` leaves); `ITranscripts.HasMessages(SessionId)`; `IWorktreeIncludeCopier.CopyAsync(FolderPath repository, FolderPath worktree, ...)`; `IRecentRepositories.ReadRecentRepositoriesAsync()` answers `IReadOnlyList<FolderPath>` and `RecordRecentRepositoryAsync(FolderPath)`. Adapters read `.Value` where they build arguments or paths, so `ClaudeCli` and `ClaudeTranscripts` change one token each. `Architecture\PortParametersShould.TakeDomainValues` reflects over every interface in `Source191.Vantage.Ports` and fails for a parameter named `sessionId`, `jobId`, `directory`, `repository`, `worktree` or `branch` whose type is `string`, unless its interface is on `Kept` with a reason; `KeepNoStaleEntry` fails when a kept interface no longer has such a parameter, as `NullFreeModelsShould` does. The names are explicit rather than `*Id` so `IPackageVersions.GetAsync(string packageId)` (no Domain value) is not caught, and `path` is left out because `IFolders` and `IFolderDeleter` take file paths too. `IGit` is the one `Kept` entry: "seventeen methods and about forty call sites; migrates in its own change". Alternative: restate the rule as "strings" and strip `SessionName`, `OpeningPrompt`, `FolderPath`, `BranchName` and `RemoteRepository` from `IClaudeCli`, `IPullRequests` and `ICreatedWorktrees`; rejected, because the values carry the checks (`SessionId`'s shape, `FolderPath`'s normalising) the adapters would otherwise repeat.

### Recent repositories are `FolderPath` end to end
`JsonFileStore`'s private `RecentRepository(FolderPath Path, DateTimeOffset UsedAt)` serialises through the converter already in `Options` as the plain string the files hold now, and `RecentFile(FolderPath repository)` keys on `repository.Key`, so the question of comparing two spellings cannot arise (I-11 by construction). A recorded entry that no longer parses (a relative path from an old file) reads as a corrupt file and is skipped, where today `RepositoryCatalogue.Paths` skipped it after reading; the same rows result. `ImportLegacyRecentAsync` reads the old `List<string>` and keeps `Parsed<FolderPath>()`. `InMemoryState` holds `List<FolderPath>` and removes duplicates by `Equals`. `WizardState.Open` and `RepositoryCatalogue.Choices` take `IReadOnlyList<FolderPath>`, and `Choices` no longer parses the recent list. Alternative: key on `FolderPath.TryParse(...) ? path.Key : ToUpperInvariant()` and keep strings at the port; rejected as a second rule for a case the port change removes.

### `ClaudeExecutable` filters as every other search does
`PathFolders.Searchable(pathFolders).SelectMany(...)` on the batch-file search. `Locate()` already passes a filtered list, so nothing a user sees changes; the public overload now keeps the rule `security.md` states for it.

### `IDesktop.OpenAsync` throws two named types; callers catch what they can answer
After `editor-not-found`: `OpenAsync` documents "throws `NoApplicationException` when Windows has no application for the file's type, and `ProgramNotStartedException`, with the reason, when nothing else could be started (PowerShell missing, the open script failing); a caller with something to undo or say catches them, one with nothing lets them reach the screen as a failed status". `Desktop` throws `ProgramNotStartedException` at `:26` and `:35` in place of `InvalidOperationException`; its message is unchanged. `OpenProblemReportHandler` catches both (a machine with no browser gives no association for `https`) into `NotOpened(reason)`, so the crash file stays as today. `OpenPullRequestHandler` stays bare: the screen's `Failed:` line already carries the reason and there is nothing to undo. `OpenSolutionHandler` catches `NoApplicationException` as `editor-not-found` has it and lets `ProgramNotStartedException` through. Alternative: an `OpenResult` (`Opened`, `NotOpened(reason)`) from the port; rejected because it forces the two bare callers to map a case into new outcome records, wording and tones (a user-visible change of words, outside a `skip_specs` change) for a failure the screen already reports. Reusing `ProgramNotStartedException` for `OpenAsync` extends `editor-not-found`'s meaning ("the program Windows was asked to start did not start") to the PowerShell child and the associated application; a third exception type was considered and rejected as one more name for the same fact.

## Risks / Trade-offs

- [`editor-not-found`, `listed-name` or `process-registry-one-path` lands after this change] → their authors and this change's each rebase; the `IDesktop` tasks here cannot start until `editor-not-found` is on `main`, so they are last in tasks.md and say so.
- [`tidy-composition-root` moves the wiring lines this change edits] → whichever lands second rebases; the lines are the `Desktop`, `EffectPorts`, `DeleteSessionHandler` and `RemoveWorktreeHandler` constructions, wherever they sit.
- [A legacy `recent\*.json` entry that is not a full path is now skipped at read rather than at the catalogue] → the wizard shows the same rows; `JsonFileStoreShould` pins that a file holding a relative path reads as absent and the rest are kept.
- [NetArchTest counts an interface's implementers as dependants] → the deleter fact expects the two implementations by name, so a third implementation also fails it, which is wanted.
- [A file written by an earlier version under the old key (a spelling `FolderPath` normalises, such as a trailing separator from a legacy import) is never found by the new `RecentFile` and would read beside its re-recorded twin] → every path `LaunchService` has recorded since `FolderPath` existed is already normalised, so its key is unchanged; for the rest, `ReadRecentRepositoriesAsync` answers distinct paths, newest first, and `JsonFileStoreShould` pins that two files for one folder read as one entry.
- [The `Kept` list in `PortParametersShould` is a standing excuse for `IGit`] → `KeepNoStaleEntry` removes the excuse the day `IGit` migrates, and the proposal names that change.

## Migration Plan

Nothing to migrate: the recent-repositories files keep their strings and keys are recomputed from the path on each write. Rollback is reverting the pull request.
