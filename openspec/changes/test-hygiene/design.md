# Design

## Context

See proposal.md for why. The fakes live in `test\Source191.Vantage.TestDoubles`, a project with no test framework that both test projects reference, and already hold two patterns this change extends: `FakeProcessRunner` guards its lists with a `Lock` and has `Fail(Exception)`; `FakePullRequests` has one `TaskCompletionSource` that `Hold()` arms and `Release()` completes for every call at once (`FakePullRequests.cs:16,50-59,61-75`). `PullRequestCatalogue` runs at most four host lookups at once through a `SemaphoreSlim(4)` (`PullRequestCatalogue.cs:23,100`), and the enricher and the inventory start its refresh without awaiting it (`SessionRowEnricher.cs:39`, `WorktreeInventory.cs:59`). `FolderDeletion.RefuseRootsAndRelativePaths` (`FolderDeletion.cs:30-36`) is the rule `FakeFolders.DeleteTree` lacks; `Folders` (`Infrastructure\Files\Folders.cs`) enumerates with `Directory.Enumerate*`, which throws `DirectoryNotFoundException`, and reads lines with `File.ReadLines`, which throws `FileNotFoundException`, while `FilesIn` checks existence first. `TerminalException` is a `Ports` type, so the fake can name it. The root `.editorconfig` has three naming rules at `suggestion` (`.editorconfig:202-212`) covering interfaces, types and non-field members, none for fields; `test\.editorconfig` holds only the expression-bodied exemption. `EnforceCodeStyleInBuild` and warnings-as-errors are on in `Directory.Build.props`. xunit.v3 4.0.2 runs test classes in parallel, each class its own collection.

## Goals / Non-Goals

**Goals:**
- No test waits on wall time to prove something did or did not happen: every wait has a deadline and every absence is proved by a structural fact (a held slot, a recorded call).
- Each fake refuses or throws where its adapter does, so a Core test that relies on an adapter's rule fails in Core rather than passing on the fake's leniency.
- One home for the reflection builder, the placeholders and `Noon` in Core.Tests.
- The blank-line and private-field naming conventions become build facts, scoped so that `src` is untouched.

**Non-Goals:**
- Changing what a handler does when Windows Terminal refuses a tab.
- Reaching `tools\HeadlessTerminal` with the new rules beyond what the root `.editorconfig` already applies to it.
- Making `FakeFolders` model attributes, links or read-only files.

## Decisions

**Per-call holds in `FakePullRequests`, not a counter.** `Hold()` switches the fake into a mode where each `ListAsync` enqueues its own `TaskCompletionSource` (under the gate, after recording the call); `ReleaseOne()` completes the oldest, `Release()` completes all and leaves the mode. `WhenCalledAsync(int count)` is a list of `(count, TaskCompletionSource)` waiters completed under the gate as the count is reached, answered already complete when it has been. The semaphore fact then reads: hold, refresh twelve, `await WhenCalledAsync(4)`, `Calls.Count` is 4 because all four slots are held, `ReleaseOne()`, `await WhenCalledAsync(5)`, `Calls.Count` is 5, `Release()`, await the refresh, 12. The alternative, a single release with a `Task.Delay`, is what is being removed.

**The branch facts await the calls they expect and assert the set requested, with no seam.** After `await WhenCalledAsync(1)` in `LookUpEachRowsBranch` (`fix`) and `WhenCalledAsync(2)` in `LookUpOnlyTheBranchesWithRows` (`fix-1`, `fix-2`), `Requests` is asserted equal to those branches. The absence half (a detached head is never asked for) is already proved where the catalogue's own task is awaited: `PullRequestCatalogueShould.AskForOneBranchAtATime` and `AnswerNoBranchForADetachedOrUnknownHead`. A seam exposing the fire-and-forget task would be a `src` change for a test's convenience. `HoldACallOpenUntilReleased` becomes deterministic by the same route: the call is recorded under the gate before it awaits its hold, so after `WhenCalledAsync(1)` the task cannot be complete.

**`FakeFolders` mirrors the adapter's exceptions, one method at a time.** `DeleteTree` throws `IOException` when `!Path.IsPathFullyQualified(path)` or the normalised path equals its `Path.GetPathRoot`, before touching the sets; `Directories`, `Files` and `IsEmpty` throw `DirectoryNotFoundException` when the folder is not declared; `Lines` throws `FileNotFoundException`; `FilesIn` keeps answering empty, as the adapter does. `WithFile` declares the file's folder already, so fixtures that declare files are unaffected. The alternative, a shared `IFolders` contract test run over both the fake and `Folders`, is better but needs a temporary folder in Core.Tests, which the project avoids; `FakeFoldersShould` pins the fake alone.

**`FailTheOpenWith` on `FakeWindowsTerminal` pins propagation, not a policy.** `OpenTabAsync` throws the exception when it is set, after recording nothing. The three handler facts assert `Should.ThrowAsync<TerminalException>` and what the fakes hold afterwards: `OpenTabHandler` has written the pending registration (`OpenTabHandler.cs:45`) before the tab is refused (`:47`), so a pending registration remains; `StartSessionHandler` has started the session before `OpenTrustTabAsync` or `tabs.OpenAsync` throws; `ResumeSessionsHandler` has removed and resumed the job before `openTab.OpenAsync` throws (`:28-41`), and the loop stops, so later sessions are not resumed. Those are today's facts, and the dispatcher reports the exception as `StatusMessage.Failed`; whether a refused tab deserves an outcome case and a tidy-up is a `src` decision for a later change, which these facts will then rewrite. The alternative, catching in the handlers now, is out of scope.

**`FakeProcessRegistry.Terminate` ends the tree.** Descendants are found by walking `tree` from the id and removed from `running` and `tree`; `Terminated` records only the id asked for, which `CloseEmptyTerminalsHandlerShould` asserts (`[4242]`). `Snapshot` appends a `ProcessFacts(id, 0, string.Empty)` for each `running` id absent from `tree`; `ProcessTree.Under` keeps children by `ParentId`, so a parent of 0 adds no child to any measured tree.

**`Fixtures` is a static class in Core.Tests.** `Build(Type)` is the ten-line constructor search and invoke; `Placeholder(Type)` is the union switch (today `StatusTonesShould`'s, which is a superset of the other two) with one message; `Noon` is `2026-10-23 12:00 UTC`, the date 19 of the 28 declarations already use. The nine files on other dates (`UpdateCheckShould` 25 October; `ProcessTreeShould`, `DiagnosticLogShould`, `DiagnosticsPrivacyShould`, `MemoryBreakdownShould` 29 October; `DetailLoaderShould`, `DetailSourcesShould`, `SessionActivityShould` 30 October; `TerminalTabShould` 1 November) adopt it, and a fact that spells the date in expected text is updated; `DetailSourcesShould.SummerNoon` stays. `SessionTestData.Noon` is removed in favour of `Fixtures.Noon`. The two Infrastructure.Tests declarations stay, with a note, because that project does not reference Core.Tests; moving `Noon` alone into TestDoubles was considered and rejected as a second home for a value `Build` and `Placeholder` sit beside.

**Naming rules at warning through IDE1006.** A naming rule's own `severity` is honoured only by IDEs ([Code-style naming rules](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/style-rules/naming-rules)); the build needs `dotnet_diagnostic.IDE1006.severity = warning`. Two new rules: `private_fields_camel_case` (kind `field`, accessibility `private`) and `private_static_fields_pascal_case` (`required_modifiers = static`, which includes `const`), the more specific winning under the documented rule order, so `Noon`, `Markers`, `Claude` and `Pwsh` keep their case. The three existing rules rise to warning with IDE1006; the solution build is the check.

**IDE2000 in `test\.editorconfig`.** `dotnet_style_allow_multiple_blank_lines_experimental = false` and `dotnet_diagnostic.IDE2000.severity = warning` go beside the IDE0022 exemption, so the nine `src` sites (`Views\SessionsViewState.cs:35`, `Views\WorktreeRow.cs:32-33`, `WorktreeInventory.cs:237`, `Domain\WhereLabel.cs:93`, `Tui\ConfigScreenDefinition.cs:23`, `Tui\SessionsScreenDefinition.cs:26`, `Tui\TableBody.cs:259`, `Tui\WorktreesScreenDefinition.cs:18`) stay someone else's and no version rises. The missing-blank-line-before-`[Fact]` case has no IDE rule and is fixed by hand.

**`DesktopShould` in a non-parallel collection.** A sealed `ProcessEnvironmentCollection` class in Infrastructure.Tests carrying `[CollectionDefinition("Process environment", DisableParallelization = true)]`, and `[Collection("Process environment")]` on `DesktopShould`; a future test that reads the environment joins the same collection.

## Risks / Trade-offs

- [A stricter `FakeFolders` breaks a fixture that enumerated an undeclared folder] → 13 test files build one; the fake task runs the solution's tests and declares the missing folders in the fixtures that relied on empty answers, as its own step.
- [`Terminate` removing descendants changes a tree fact] → `ProcessTreeShould`, `MemoryBreakdownShould`, `AdoptSessionHandlerShould` and `CloseEmptyTerminalsHandlerShould` run after the change; a fact that terminated a parent and still read a child is corrected to the adapter's behaviour.
- [IDE1006 at warning finds a naming violation in `src` or `tools`] → a grep finds none (no camelCase static readonly, no PascalCase private instance field); if the build finds one, it is fixed in the change that owns the file and the rule lands after.
- [`Fixtures.Noon` moves a date a fact depended on] → each adopting file's facts run; expected text spelling the date is updated in the same commit.
- [`small-repetition` adds IDE2000 first, or in the root] → whichever lands first adds the setting; this change then only fixes the test sites, and never adds a root rule.
- [`DisableParallelization` slows Infrastructure.Tests] → `DesktopShould` is one class of a few seconds; the rest of the suite still runs class-parallel around it.
