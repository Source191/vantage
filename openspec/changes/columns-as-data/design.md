# Design

## Context

`IScreenDefinition<TState, TRow>` (`src\Source191.Vantage.Tui\IScreenDefinition.cs`) describes a table by four separate members: `Columns` (the `ColumnHelp` list from `Wording`), `ElasticColumn` (an index or null), `Cell(row, column, now, width)` and `CellPaint(row, column)`. `TableBody` copies the names out of `Columns` (`TableBody.cs:74`), and `StyleColumns` (`:474-491`) sets `MaxWidth = 28` with a `…` indicator where the name is `"NAME"` and `Alignment.End` where it is `"AGE"`; `ElasticWidth` (`:497-521`) and `Redraw` (`:244`) hand the elastic column's width to `Cell`, where `WhereLabel.Fit` and `ConfigScreenDefinition.Middle` elide the middle. The three definitions switch on the column index, `SessionsScreenDefinition` through the constants `TabColumn = 1` and `RepositoryColumn = 3` (`:14-15`), which its `CellPaint` also uses. `ConfigScreenDefinitionShould` (`test\Source191.Vantage.Core.Tests\Tui`) is the only test of a definition and calls `Cell(row, 1, ...)`. `SmokeScript` and `WordingOfKeysAndColumnsShould` read the `Wording` lists, not the definitions. See proposal.md for why.

## Goals / Non-Goals

**Goals:**
- One place per column says what it is called, what its cell says and how it fits; `TableBody` reads that and compares no header text.
- A test per definition fails when its columns and the `Wording` list disagree in order or count, or when a view has no elastic column or two.

**Non-Goals:**
- Changing how Terminal.Gui cuts a capped cell or sizes a column; only where the instruction comes from changes.
- Any other `IScreenDefinition` member, the detail pane, the tooltips' words or the key bar (`table-body-collaborators` and `wording-one-home` own those).

## Decisions

### A column is a `TableColumn<TRow>` record in Tui
`TableColumn<TRow>(ColumnHelp Help, Func<TRow, DateTimeOffset, int, string> Cell, ColumnFit Fit, Func<TRow, CellPaint> Paint)`, sealed, in `src\Source191.Vantage.Tui\TableColumn.cs`, with a static `Plain(help, cell, fit)` whose paint is always `CellPaint.None`, so the Worktrees and Config definitions and five of the six sessions columns name no paint. `IScreenDefinition.Columns` becomes `IReadOnlyList<TableColumn<TRow>>`, and `ElasticColumn`, `Cell` and `CellPaint` leave the interface, since each is now read off the column. `Paint` has to move with `Cell`, or `CellPaint(row, column)` would still need `TabColumn` to know which column is TAB. The record lives in Tui beside `CellPaint` and `TableDetail` because its `Paint` answers a Tui type and the interface it serves is Tui's; `Wording` stays words only. Alternative: keep `CellPaint(row, column)` on the interface and leave `TabColumn` as the one surviving index, which keeps the coupling the change exists to remove.

### `ColumnFit` is a closed record hierarchy, not an enum
`ColumnFit` (`src\Source191.Vantage.Tui\ColumnFit.cs`, cases nested in their base as the house rule for a closed hierarchy says): `Natural`, `Capped(int Cells)`, `Elastic`, `RightAligned`. `Capped` carries its 28 because the cap is the column's property, declared where NAME is declared, and `TableBody` keeps only the ellipsis it draws. Every switch over it names all four cases and throws `UnreachableException` from its discard, as `CellPaint`'s do. Capped and Elastic are different mechanisms and stay so: Capped is a `ColumnStyle` (`MaxWidth`, `TruncationIndicator`, cut at the end by Terminal.Gui); Elastic is the width `TableBody` computes and hands to `Cell`, which the definition's own `Fit` or `Middle` uses to elide the middle. Alternative: an enum with the 28 left as `TableBody.LongColumnCap`, exhaustive by CS8509 but putting the one number the spec states back in the Tui rather than on the column.

### `Wording` names each column, and the lists are built from the names
`WordingOfScreens.cs` gains a public static `ColumnHelp` per column (`NameColumn`, `TabColumn`, `StateColumn`, `RepositoryColumn`, `PullRequestColumn`, `AgeColumn`, `WorktreeColumn`, `HealthColumn`, `LastCommitColumn`, `SessionColumn`, `SettingColumn`, `ValueColumn`; none collides with a `Wording` member today), declared above the three lists, which become `[NameColumn, TabColumn, ...]`; static initialisers run in textual order, so the members must sit above the lists. A definition then writes `new(Wording.AgeColumn, ...)` and no index into a `Wording` list appears anywhere; `SessionsScreenDefinition`'s `TabColumn` and `RepositoryColumn` index constants are deleted, and the `Wording` members of those names are help entries. The fact for this uses reference equality (`ShouldBeSameAs` per entry), since `ColumnHelp` is a record and value equality would pass with the words written twice. The lists stay the one home for the words and the order, and the help, tooltips and `SmokeScript` keep reading them. Alternative: `Wording.SessionsColumns[5]` in the definitions, which the ordering fact would also catch but which is the index coupling the review named.

### `TableBody` reads `Fit` and finds the elastic column itself
`StyleColumns` switches on each column's `Fit`: `Capped` sets `MaxWidth` and the `…` indicator, `RightAligned` sets `Alignment.End`, `Natural` and `Elastic` set nothing there. `ElasticWidth` takes the index of the one `Elastic` column (`Columns.Single(column => column.Fit is ColumnFit.Elastic)`, found once in the constructor) and keeps its arithmetic; the "no elastic column" branch and `ElasticColumn`'s "or null when every column has its natural width" summary go, because every view has one and the definition facts hold it, so the branch would be untested dead code; `Redraw`'s callback and `WidestCell` call `Columns[column].Cell(row, now, width)`; `CellColour` calls `Columns[args.ColIdex].Paint(row)`; the header tooltip reads `Columns[header.Column].Help`; `columnNames` comes from `Help.Name`. The styling of one `ColumnStyle` from a `ColumnFit` is a static `ColumnFits.Apply(style, fit)` so `Core.Tests` can assert the `MaxWidth`, indicator and alignment on a `new ColumnStyle()` without an application running; if `ColumnStyle` turns out to need one, the smoke check stays the net and the method stays private. Alternative: leave `StyleColumns` keyed on names read from the new columns, which is the bug with one more hop.

### The definition facts live beside `ConfigScreenDefinitionShould`
`SessionsScreenDefinitionShould` and `WorktreesScreenDefinitionShould` in `test\Source191.Vantage.Core.Tests\Tui`, written first as the red step (they fail to compile until the interface changes, since an interface with three implementers and one consumer cannot be moved in green halves), each asserting `Columns.Select(column => column.Help)` equals the `Wording` list, exactly one `Fit` is `Elastic`, and the duration column is `RightAligned` (NAME `Capped(28)` on Sessions). `SessionsScreenDefinition` is built as `ConsoleScreen` builds it: `StateTransitionNotifier(StringWriter)`, `SessionActivity(FakeTimeProvider)`, a made-up claude path, `FolderLabels(() => [C:\Users\me\source\repos], C:\Users\me)` and a real `SessionDetails` over `DetailLoader(new GitCli(fakeProcesses, "git"), InMemoryState, activity)`, as `DetailSourcesShould` does, because there is no `IDetailSource` fake and the house style wants real collaborators. Alternative: a one-line `IDetailSource` fake in TestDoubles, which the facts never call.

## Risks / Trade-offs

- [Terminal.Gui's `MaxWidth` with a `TruncationIndicator` may count the ellipsis inside or outside the 28] → the spec says "cut to 28 cells ending with an ellipsis", which is what the screen shows today; the smoke check captures the Sessions view and the owner reads a long name at 120 columns.
- [`table-body-collaborators` moves `StyleColumns`, `ElasticWidth` and `WidestCell` into a `ColumnSizing` and slims `IScreenDefinition`; `wording-one-home` edits the same definitions] → the second to land rebases; the `Fit` reading moves with the sizing code, and nothing here depends on either.
- [Twelve more public members on `Wording`] → each is one line and the words move nowhere; the lists are shorter to read as names than as sentences.
- [A `Func` per cell loses the one-method `Cell` switch that read as a table] → the column list reads as the same table, one row per column, and gains the fit beside each.
