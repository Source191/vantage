# Source191.Vantage

The packed tool: `Program.cs` and its `Composition` folder, the only composition root, wire Core, Infrastructure and Tui together, and packing includes those three projects. `Program.cs` keeps the process-wide start (`SharedParts`, Terminal.Gui's logger, the crash hooks and the command line); `LaunchParts` is the console's and `vantage here`'s shared preamble, which checks `RequiredPrograms`, prints the sentence and exits 1 when Claude Code or git cannot be run; `ConsoleComposition`, `HereComposition` and `TerminalSetupComposition` construct one command each. Everything here is untested wiring, checked by the build, the hand-off check and CI's smoke check: each decision it once held is a tested class in Core's `Application` (`ConsoleLoads`, `Started.From`, `UpdateCheckSwitch`, `HeaderSettingsRow`, `RequiredPrograms`). Construction is by hand: a dependency injection container was weighed in the `tidy-composition-root` change and rejected, because many arguments are strings, delegates or several values of one type, start-up is async, and a missing registration would fail at run time rather than in the build. The user guide is the repository's [README](../../README.md), which is also the package readme on nuget.org; `THIRD-PARTY-NOTICES.txt` travels beside the tool, as the licences of the packed dependencies ask.

## Package settings

- **`SatelliteResourceLanguages` `en`:** Vantage is English only, so the translated resources of System.CommandLine and Terminal.Gui are neither built nor packed, and those libraries' own messages stay English on every Windows display language.
- **`IncludeSourceRevisionInInformationalVersion` false:** `vantage --version` prints exactly the package version that nuget.org and the GitHub Release show, with no `+<commit>`. The commit is still recorded in the package's repository metadata. The `check` job asserts this on the installed tool.
- **`PackageReleaseNotes`:** the whole of the root `CHANGELOG.md`, read at evaluation with `File.ReadAllText`, so nuget.org shows it and the update check reads it from the newest release's nuspec (`NuGetPackageVersions.NotesAsync`). It is packed as written, Unreleased and Internal included: Vantage drops both when it reads the notes, so packing needs no script. nuget.org takes at most 35,000 characters, which `Assert-ChangelogUpdated.ps1` holds the file under.
- **`CHANGELOG.md` beside the tool:** copied to the output and so packed in `tools\net10.0\any`, as `vantage.ico` is, where `PackagedReleaseNotes` reads it on the first start of a new version without a network request.
- **The `RemoveNonWindowsNativeAssets` target:** Terminal.Gui depends, through TextMateSharp, on Onigwrap, whose `libonigwrap` ships for thirteen platforms; the target drops every published file whose runtime identifier is not a Windows one, so the package keeps only `win-x64`, `win-arm64` and `win-x86`, and the shared pack step fails if any other platform's assets come back. RID-specific tool packages were tried instead and rejected: they install a `vantage.cmd` shim and a versioned executable path that breaks `U` and the terminal profile after every update.
- **`ContinuousIntegrationBuild`:** set under GitHub Actions in the root `Directory.Build.props`, which explains it, so the packed assemblies are deterministic.
- **`InvariantGlobalization`:** the one project where the setting takes effect, because only an executable's `runtimeconfig.json` carries it; the libraries leave it off (their READMEs say why) and the test projects set it so they run as the tool does.
- **`vantage.ico`:** `assets\icon\vantage.ico` is copied beside `vantage.exe`, where `vantage setup-terminal` finds it and copies it next to the Windows Terminal fragment as the profiles' tab icon.
